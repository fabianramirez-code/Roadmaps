# jarsigner, keytool, jmod, jimage, jwebserver

# jarsigner, keytool — firma y almacenes de claves

[`keytool`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/keytool.html) **crea y consulta claves y certificados en un almacén; [`jarsigner`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jarsigner.html) firma y comprueba archivos Java Archive (JAR), que agrupan clases y recursos**. Public-Key Cryptography Standards #12 (PKCS12) es un [formato de almacén de claves](https://www.rfc-editor.org/rfc/rfc7292) protegido por contraseña. El certificado **autofirmado** de este ejemplo solo sirve para pruebas: no acredita la identidad ante terceros. No versiones almacenes ni contraseñas; en uso real deja que las herramientas **soliciten la contraseña** en vez de pasarla en la línea de comandos (puede quedar en el historial o visible para otros procesos).

Trabaja dentro de `Ejemplos_020`: reutiliza `Prueba.java` de la nota 017 y su JAR mínimo (`myapp.jar`), compilándolo y empaquetándolo aquí con los comandos de esa nota. Para el certificado de prueba, introduce los datos que pida `keytool`; `-dname` evita las preguntas sobre identidad, pero **no** la petición de contraseña. Rivest–Shamir–Adleman (RSA) es el [algoritmo de clave](https://docs.oracle.com/en/java/javase/25/docs/specs/security/standard-names.html#keypairgenerator-algorithms) elegido para el ejemplo.

```bash
keytool -genkeypair -alias prueba -keyalg RSA -keysize 2048 -validity 30 -keystore pruebas.p12 -storetype PKCS12 -dname "CN=Prueba" # Pide contraseña; crea certificado autofirmado válido 30 días
keytool -list -keystore pruebas.p12 -storetype PKCS12 # Muestra las entradas
keytool -exportcert -alias prueba -keystore pruebas.p12 -storetype PKCS12 -file prueba.cer # Exporta solo el certificado público
jarsigner -keystore pruebas.p12 -storetype PKCS12 -signedjar Prueba-firmado.jar myapp.jar prueba # Firma una copia del JAR
jarsigner -verify Prueba-firmado.jar # Comprueba la firma; advierte que el certificado es autofirmado
```

## Comprobación de resultados

Consulta el certificado y las entradas firmadas. En el JDK 25 probado, `keytool` falló con `MissingFormatArgumentException` al mostrar certificados en español; `-J-Duser.language=en` evita ese fallo (la contraseña del almacén se solicita al consultar):

```bash
keytool -J-Duser.language=en -list -v -keystore pruebas.p12 -storetype PKCS12 # Alias prueba, CN=Prueba, validez de 30 días y huella SHA-256
keytool -J-Duser.language=en -printcert -file prueba.cer # Misma huella SHA-256 que en el almacén
jarsigner -verify -verbose -certs Prueba-firmado.jar # Lista las entradas y el certificado del firmante
jar tf Prueba-firmado.jar # Incluye META-INF/PRUEBA.SF y META-INF/PRUEBA.RSA (nombre derivado del alias)
```

La verificación muestra `jar verified.` y avisa del certificado autofirmado, normal en esta prueba. Para comprobar la integridad, copia el JAR firmado, **cambia el texto de `Prueba.java` y recompila `Prueba.class`** antes de reemplazar esa entrada ya firmada:

```bash
Copy-Item Prueba-firmado.jar Manipulado.jar # Conserva el original
javac Prueba.java # Tras cambiar el texto, genera una clase distinta
jar uf Manipulado.jar Prueba.class # Reemplaza la entrada firmada
jarsigner -verify Manipulado.jar # Falla: jarsigner error: java.lang.SecurityException: SHA-384 digest error for Prueba.class (código 1)
```

Añadir una entrada nueva sin firma **no** provoca ese fallo: `jarsigner -verify` puede mostrar `jar verified.` con un aviso de entradas sin firmar.

# jmod, jimage — formatos internos de módulos

[`jmod`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jmod.html) empaqueta clases de un módulo en un archivo Java Module (JMOD) para `jlink`; **un JMOD no se ejecuta directamente en tiempo de ejecución**. Para probarlo, crea en `Ejemplos_020` un `module-info.java` mínimo (no incluyas `Prueba.class` de la nota 017: pertenece al paquete sin nombre, inadmisible en un módulo):

```java
module ejemplo.modulo {
}
```

```bash
javac -d clases module-info.java # Compila el descriptor
jmod create --class-path clases ejemplo.modulo.jmod # Empaqueta el módulo
jmod list ejemplo.modulo.jmod # Enumera las entradas
jmod describe ejemplo.modulo.jmod # Muestra el descriptor y dependencias
jmod extract --dir extraido ejemplo.modulo.jmod # Extrae classes\module-info.class
```

[`jimage`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jimage.html) inspecciona la imagen de módulos `lib\modules` de un entorno de ejecución, ya sea el Java Development Kit (JDK) instalado o una imagen creada con `jlink`. Si `JAVA_HOME` apunta al JDK, estos comandos limitan la extracción a una clase; sin `--include`, `extract` extraería **toda** la imagen:

```bash
$imagen = Join-Path $env:JAVA_HOME 'lib\modules' # Ruta del JDK instalado
jimage list --include 'glob:**/java/lang/Object.class' $imagen # Lista la clase seleccionada
jimage info $imagen # Cabecera de la imagen
jimage extract --dir imagen-extraida --include 'glob:**/java/lang/Object.class' $imagen # Extrae solo esa clase
```

# jwebserver — Simple Web Server (Java 18+, JEP 408)

[`jwebserver`](https://openjdk.org/jeps/408) sirve **archivos estáticos** mediante peticiones GET y HEAD (lectura de contenido y de cabeceras, respectivamente). Es para pruebas y prototipos, **no para producción**; sirve únicamente un directorio preparado con archivos que puedas mostrar, no el proyecto completo. La misma propuesta incluye una interfaz de programación para crear servidores sencillos desde Java.

| Opción | Función |
|---|---|
| `-p 8000` | Puerto de escucha. |
| `-d web` | Directorio de archivos que se sirven. |
| `-b 127.0.0.1` | Dirección local: solo accesible desde este equipo. |
| `-o info` | Nivel de información mostrado (`none`, `info` o `verbose`). |

Tras colocar un `index.html` en el directorio `web` de `Ejemplos_020`, mantén abierta la primera terminal; consulta desde una segunda en ese mismo directorio y detén el servidor con Ctrl+C:

```bash
jwebserver -p 8000 -d web -b 127.0.0.1 -o info # Primera terminal
Invoke-WebRequest http://127.0.0.1:8000/ # Segunda terminal: solicita el índice
```

# Comandos para Linux/macOS

Solo cambia la petición desde la segunda terminal (si no tienes PowerShell); usa `/` al inspeccionar rutas extraídas:

```bash
curl http://127.0.0.1:8000/ # Comprueba la respuesta
```
