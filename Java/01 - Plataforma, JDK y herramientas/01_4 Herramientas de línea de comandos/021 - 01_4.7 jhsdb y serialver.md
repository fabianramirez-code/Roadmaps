# jhsdb y serialver — usos puntuales

## jhsdb — diagnóstico excepcional

[`jhsdb`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jhsdb.html) usa el Serviceability Agent (SA, agente de diagnóstico) de HotSpot, la implementación de la Java Virtual Machine (JVM, máquina virtual de Java) incluida en este Java Development Kit (JDK, kit de desarrollo de Java). Permite analizar un proceso en ejecución o, tras un fallo, un volcado de memoria del proceso (*core dump*). Para el diagnóstico habitual usa `jcmd` (nota 019); reserva `jhsdb` para casos avanzados, como una JVM colgada o que ha fallado. **Adjuntarse a un proceso vivo lo detiene durante el análisis** y requiere permisos suficientes: evita hacerlo sin evaluar el impacto.

Modos principales: `clhsdb` (consola interactiva), `hsdb` (interfaz gráfica), `debugd` (servidor remoto, obsoleto en JDK 25), `jstack` (hilos), `jmap` (memoria), `jinfo` (opciones y propiedades) y `jsnap` (contadores). `--pid <pid>` selecciona un proceso vivo; para un volcado, `--core <archivo>` **debe ir junto con** `--exe <ejecutable>` de ese proceso. Los volcados y las propiedades pueden contener información sensible.

Para una prueba local, reutiliza `Espera.java` y la forma de identificar su process identifier (PID, identificador de proceso) de la nota 019: déjalo ejecutándose en una terminal y, en otra, sustituye `<pid>` por el número obtenido. Detén `Espera` con Ctrl+C al acabar. En este JDK 25 para Windows, la consulta de hilos sí pudo adjuntarse; no se probó el análisis de un *core dump* ni los demás modos sobre un proceso.

```bash
jhsdb jstack --pid <pid> # Muestra las trazas de los hilos mientras pausa el proceso
```

## serialver — identificador de versión de serialización

[`serialver`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/serialver.html) calcula el `serialVersionUID` predeterminado de una clase que implementa `Serializable` (interfaz de [serialización de objetos](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/serial-arch.html)). Crea `Mensaje.java` dentro de `Ejemplos_021` con este ejemplo mínimo:

```java
import java.io.Serializable;

public class Mensaje implements Serializable {
    private String texto;
}
```

```bash
javac -d clases Mensaje.java        # Compila la clase
serialver -classpath clases Mensaje # Imprime la declaración calculada
```

Si la clase está en el directorio actual del classpath, basta `serialver Clase` (por ejemplo, `serialver Mensaje`). Copia el valor obtenido y declara `private static final long serialVersionUID = <valor>L;` **dentro de la clase** cuando vayas a mantener su formato serializado: así una modificación compatible no cambia accidentalmente el identificador calculado ni impide leer objetos escritos por una versión anterior. El identificador por sí solo no garantiza que todos los cambios de campos sean compatibles.

**Cuándo se usa en la práctica**

1. **Clase ya desplegada sin identificador declarado:** si hay objetos guardados (archivos, caché, sesiones o colas) y debes modificarla, ejecuta `serialver` sobre la versión antigua compilada. Java calcula el identificador a partir de la estructura de la clase; un cambio podría alterarlo y hacer ilegibles los datos antiguos.
2. **Dos versiones que deben entenderse:** por ejemplo, un cliente y un servidor con distintas versiones de la clase. Comparten el mismo identificador y la deserialización determina si los cambios permiten leer los datos.
3. **Diagnóstico:** una `InvalidClassException` muestra los dos identificadores en conflicto. Con `serialver` ves cuál produce cada versión compilada y localizas dónde cambió la clase.

**Dónde no hace falta**

- Si empiezas una clase nueva, puedes declarar un valor como `1L` sin usar la herramienta.
- Muchos proyectos modernos no usan la serialización nativa de Java (`Serializable`): prefieren [JavaScript Object Notation (JSON, formato de intercambio de datos)](https://www.json.org/json-es.html), [Protocol Buffers (formato de intercambio de datos estructurados)](https://protobuf.dev/overview/) o [Apache Avro (formato de serialización de datos)](https://avro.apache.org/docs/current/), que no dependen de este identificador.
- La serialización nativa tiene riesgos de seguridad al deserializar datos no confiables; por eso se evita en código nuevo.
