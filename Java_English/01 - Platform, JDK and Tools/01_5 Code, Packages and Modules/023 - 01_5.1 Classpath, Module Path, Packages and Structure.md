# Classpath, Module path, Packages and structure

# Classpath — resolution and order, wildcard `lib/*`

The *classpath* tells Java tools and the runtime where to look for classes: directory roots containing `.class` files or Java Archive (JAR) files, which bundle classes and resources. When searching for a class, **entries are scanned from left to right** and **the first match wins**. A directory is a package root; a JAR contains those paths inside the archive. See the official [`java`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html) and [`javac`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html) manuals.

| Option | Use |
|---|---|
| `-cp path` / `--class-path path` | Sets the class search path for the command; overrides the `CLASSPATH` environment variable when supplied. |
| `CLASSPATH` | Default search path when the option is absent; passing it explicitly is preferable to avoid surprises. |
| `"lib/*"` | Includes JARs directly in `lib`, not subdirectories or loose `.class` files; **their order is not guaranteed**. Quotes prevent PowerShell from interpreting the wildcard. |

On Windows, separate multiple entries with `;`. For the example, create the following two files (the main class explicitly imports the other class):

`src\com\example\util\Greeting.java`:

```java
package com.example.util;

public class Greeting {
    public static String text() {
        return "Hello";
    }
}
```

`src\com\example\app\Main.java`:

```java
package com.example.app;

import com.example.util.Greeting;

public class Main {
    public static void main(String[] args) {
        System.out.println(Greeting.text());
    }
}
```

Neither class needs to import `java.lang`, which is automatically available. First run from the examples directory with both classes compiled into `out`; then package only `Greeting` to demonstrate searching in a JAR and recompile `Main` into `app`:

```bash
javac -d out src\com\example\util\Greeting.java src\com\example\app\Main.java # Compile both classes
java -cp out com.example.app.Main # Hello
jar --create --file lib\greeting.jar -C out com/example/util/Greeting.class # lib must exist
javac -cp lib\greeting.jar -d app src\com\example\app\Main.java # Compile only Main
java -cp "app;lib/*" com.example.app.Main # Hello; PowerShell passes the wildcard to Java
```

These actual files in `Examples_023` use the same names but belong to the **default package** (for practice only); normally packages are used.

`Examples_023\Greeting.java`:

```java
public class Greeting {
    public static String text() {
        return "Hello";
    }
}
```

`Examples_023\Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println(Greeting.text());
    }
}
```

From `Examples_023`, with `Greeting.class` already compiled into `out`, compile `Main`, specifying where to find it, and run both from that root:

```bash
javac -d out Greeting.java # Already done
javac -cp out -d out Main.java
java -cp out Main # Hello
java Main # Error: Could not find or load main class Main (out is not the current directory)
```

If the classpath contains `Main.class` but not `Greeting.class`, execution fails with `java.lang.NoClassDefFoundError: Greeting`. From the folder containing this note use `java -cp ".\Examples_023\out" Main`; from any other folder an absolute path in quotes also works:

```bash
java -cp "E:\All_Notes\Personal_Notes\Software\PRACTICAS\Java_English\01 - Platform, JDK and Tools\01_5 Code, Packages and Modules\Examples_023\out" Main # Hello
```

Do not rely on the wildcard's internal order to resolve duplicate classes.

# Module path — difference from classpath; see [[Java 10 - Plataforma avanzada|Java 10 - Advanced Platform]]

The *module path* looks for modules with a `module-info.class` descriptor. Unlike the classpath, the [Java module system](https://openjdk.org/jeps/261) declares dependencies with `requires`, restricts visibility with `exports` (strong encapsulation), and detects split-package conflicts between resolved modules. A JAR without a descriptor placed there can become an **automatic module**; classpath classes belong to the **unnamed module**. For more detail: [[Java 10 - Plataforma avanzada|Java 10 - Advanced Platform]].

| Option | Use |
|---|---|
| `-p path` / `--module-path path` | Searches for modules on the specified path. |
| `--add-modules com.example` | Adds a root module to resolve; useful when combining module and class paths. |
| `-m com.example/com.example.app.Main` | Runs the specified module's main class. |

Create `module-info.java` alongside `src` to turn the same example into a module; `java.base` is an implicit dependency and needs no `requires`:

```java
module com.example {
}
```

```bash
javac -d mods\com.example module-info.java src\com\example\util\Greeting.java src\com\example\app\Main.java # Compile the module
java --module-path mods --add-modules com.example -m com.example/com.example.app.Main # Hello
```

# Packages and directory structure — reverse-domain convention

The [`package`](https://docs.oracle.com/javase/specs/jls/se25/html/jls-7.html) declaration gives a class a fully qualified name and organizes its namespace. By convention, packages start with a reversed domain (for example, `com.example`) followed by their function (`app`, `util`). The path beneath the source root reflects the package components: `src\com\example\app\Main.java` declares `com.example.app`; `javac -d out` reproduces that structure under `out`. To run a packaged class, use its **fully qualified name**, not its short name; `out` is the classpath root, not `out\com\example\app`.

If you search for `Main` without its package, JDK 25 in English displays `Error: Could not find or load main class Main` and `Caused by: java.lang.ClassNotFoundException: Main`. Running `Main` from `app` without the `Greeting` JAR results in `java.lang.NoClassDefFoundError: com/example/util/Greeting`, caused by `ClassNotFoundException`: check the root, fully qualified name, and classpath dependencies.

# Linux/macOS Commands

Use `/` in file paths and separate classpath entries with `:` rather than `;`; other arguments remain unchanged. For the example, replace paths in the Windows commands and run the multiple-entry case like this:

```bash
java -cp 'app:lib/*' com.example.app.Main # Hello
```
