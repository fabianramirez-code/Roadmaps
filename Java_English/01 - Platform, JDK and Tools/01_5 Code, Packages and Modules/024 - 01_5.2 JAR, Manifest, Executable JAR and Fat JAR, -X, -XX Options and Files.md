# JAR, manifest, executable JAR and fat JAR, -X and -XX options and files

# JAR, manifest — `Main-Class`, `Class-Path`, `Multi-Release`

A Java Archive (JAR) is a ZIP file containing classes and resources; basic creation and listing are already covered in [note 016](../01_4%20Command-Line%20Tools/016%20-%2001_4.2%20Multi-File%20Source%20Launch,%20jshell,%20jar.md). At its root are the paths to the classes (`Main.class`, or `com/example/Main.class`); `META-INF/MANIFEST.MF` is the **manifest** containing metadata, not a class ([official specification](https://docs.oracle.com/en/java/javase/25/docs/specs/jar/jar.html)).

| Manifest attribute | Meaning |
|---|---|
| `Main-Class: Main` | Fully qualified name of the class with `main`; no `.class` suffix. |
| `Class-Path: lib/greeting.jar` | External dependencies: paths relative to the JAR's location, separated by spaces; wildcards such as `lib/*` are not supported. |
| `Multi-Release: true` | Enables alternative classes in `META-INF/versions/N/` for Java N or later (N ≥ 9); the highest compatible version takes precedence, if present. |

The format requires a final newline and a blank line at the end of each section; each physical line allows **at most 72 bytes** (not characters): long lines continue on the next line starting with a space. Do not duplicate attributes. Multi-release JARs were defined in [JDK Enhancement Proposal (JEP) 238](https://openjdk.org/jeps/238), available since Java 9; the base version must run on the Java version preceding the variant's version.

For practice, reuse `Main.java` and `Greeting.java` from note 016, from your examples directory. Create `lib` and a `MANIFEST.MF` file in that directory with these lines (including **a blank line at the end**):

```text
Manifest-Version: 1.0
Main-Class: Main
Class-Path: lib/greeting.jar
Multi-Release: true

```

Create another version of `Greeting.java` under `v9` (same signature as in note 016, but a different message):

```java
public class Greeting {
    static String from(String name) { return "Hello Java 9+"; }
}
```

```bash
New-Item -ItemType Directory out, lib, v9 -Force | Out-Null # Prepare the output paths
javac --release 8 -d out Main.java Greeting.java # Base version; JDK 25 may warn that 8 is old
javac --release 9 -d v9 v9\Greeting.java # Variant for Java 9+
jar --create --file lib\greeting.jar -C out Greeting.class # External dependency
jar --create --file app.jar --manifest MANIFEST.MF -C out Main.class # Preserve the custom manifest
jar --create --file multi.jar --main-class Main -C out Main.class -C out Greeting.class --release 9 -C v9 Greeting.class # Add the variant
```

To read **the manifest** without extracting files, use PowerShell: load the JAR as a ZIP, open `META-INF/MANIFEST.MF`, and close the readers; you can also extract it using the procedure in note 016. The [`jar` manual](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jar.html) describes `--manifest`, `--main-class`, and `--release`.

```bash
Add-Type -AssemblyName System.IO.Compression.FileSystem # ZIP API
$zip = [System.IO.Compression.ZipFile]::OpenRead((Resolve-Path .\multi.jar).Path)
try {
    $reader = [System.IO.StreamReader]::new($zip.GetEntry('META-INF/MANIFEST.MF').Open())
    try { $reader.ReadToEnd() } finally { $reader.Dispose() }
} finally { $zip.Dispose() } # Main-Class and Multi-Release
```

# Executable JAR and "fat JAR" — when to use them

`java -jar` starts the class declared in `Main-Class`. The `-cp` option is **ignored** when using `-jar`: the effective classpath comes from the JAR and its manifest, not the value specified on the command line. Therefore `app.jar` needs `lib/greeting.jar` alongside it (in its `lib` subdirectory); without that dependency, loading `Greeting` fails. `multi.jar`, by contrast, contains both classes and selects the variant on Java 9+ ([official `java` manual](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html)). Search order and wildcards for the ordinary classpath are covered in [note 023](023%20-%2001_5.1%20Classpath,%20Module%20Path,%20Packages%20and%20Structure.md).

```bash
java -jar app.jar # Hello Java, using lib/greeting.jar
java -cp "nonexistent" -jar app.jar # Hello Java: -cp does not replace Class-Path
java -jar multi.jar # Hello Java 9+ on JDK 25
```

A **fat JAR** or *uber-jar* combines the application's and its dependencies' classes and resources in a single file: useful for distributing just one file, but class or resource name conflicts, invalid signatures after modifying signed JARs, and a larger file are possible. For separate dependencies, prefer `Class-Path` with `lib/`: it lets you replace them individually, but you must distribute the entire directory. [Maven Shade](https://maven.apache.org/plugins/maven-shade-plugin/) and [Gradle Shadow](https://gradleup.com/shadow/) are tools for building fat JARs; merely putting JARs inside another JAR is not enough. **Nested JARs** in [Spring Boot](https://docs.spring.io/spring-boot/specification/executable-jar/nested-jars.html) use their own loader: they are not the flat fat JAR format and are not resolved automatically by the Java launcher.

# -X and -XX options and @argfiles; JAVA_TOOL_OPTIONS variable

`-X` options are implementation-specific (nonstandard): `-Xms` sets the initial *heap* size, `-Xmx` its maximum, and `-Xss` the stack size per thread. `-XX` groups advanced virtual machine options: `-XX:+Flag` enables a boolean option and `-XX:Flag=value` assigns a value; check availability and values in **your** JDK, as they can change. `java -X` displays the `-X` options; `-XX:+PrintFlagsFinal` lists the final values (filtered to avoid printing thousands of lines). See the [`java` manual](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#extra-options-for-java) and its [advanced options](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#advanced-options-for-java).

```bash
java -X # Help for nonstandard options
java -Xmx64m -XX:+PrintFlagsFinal -version 2>&1 | Select-String 'MaxHeapSize' # Show the applied maximum
```

An **argument file** (`@argfile`) contains launcher options and arguments separated by spaces or newlines; `#` starts a comment and quotes group text containing spaces. Create `args.txt` as plain text in the examples directory:

```text
# Options for running the application
-Xmx64m
-jar "app.jar"
```

```bash
java @args.txt # Hello Java
```

The `@` is expanded by the `java` **launcher** before processing arguments: it is not a list of arguments interpreted by `main`, nor a virtual machine option; avoid including secrets. To prevent subsequent expansions, use `--disable-@files`. The [official argument-file documentation](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#java-command-line-argument-files) details escaping and quoting.

`JAVA_TOOL_OPTIONS` injects virtual machine options when the virtual machine is created, even when `java` is not invoked directly; it cannot supply launcher-only options such as `-jar`. `JDK_JAVA_OPTIONS` prepends options to the launcher's command line (it rejects, for example, `-jar` in the variable). HotSpot also has `_JAVA_OPTIONS`, which is implementation-specific. **Do not rely on universal precedence among the three**: the launcher processes `JDK_JAVA_OPTIONS` before its arguments, while the others are applied when creating the virtual machine; when repeating an option, check the effective value in your JDK. These variables affect other Java processes in the session: remove them when done ([launcher environment](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#using-the-jdk_java_options-launcher-environment-variable)).

```bash
$env:JAVA_TOOL_OPTIONS = '-Xmx64m'; java -jar app.jar; $env:JAVA_TOOL_OPTIONS = $null # stderr: Picked up JAVA_TOOL_OPTIONS: -Xmx64m
$env:JDK_JAVA_OPTIONS = '-Xmx128m'; java -version; $env:JDK_JAVA_OPTIONS = $null # stderr: NOTE: Picked up JDK_JAVA_OPTIONS: -Xmx128m
$env:_JAVA_OPTIONS = '-Xmx256m'; java -version; $env:_JAVA_OPTIONS = $null # stderr: Picked up _JAVA_OPTIONS: -Xmx256m (HotSpot)
```

# Linux/macOS Commands

If you do not use PowerShell, read the manifest without extracting the JAR with `unzip -p` (if `unzip` is installed); to try the environment variable for only that process, put the assignment before the command. Java options and paths inside the JAR do not change.

```bash
unzip -p multi.jar META-INF/MANIFEST.MF # Show the manifest
JAVA_TOOL_OPTIONS='-Xmx64m' java -jar app.jar # Variable for this process only
```
