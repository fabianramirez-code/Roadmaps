# IntelliJ IDEA — projects, SDK per module, inspections, shortcuts

An **integrated development environment** (IDE) brings together editing, compilation and navigation. In [IntelliJ IDEA](https://www.jetbrains.com/help/idea/discover-intellij-idea.html), a **project** groups modules; each module can have its own Java Development Kit (**JDK**) and language level. The Java **Software Development Kit** (**SDK**) setting in the interface points to a JDK installation, not to the language level ([SDK configuration](https://www.jetbrains.com/help/idea/sdk.html), [modules](https://www.jetbrains.com/help/idea/configure-modules.html)).

1. Open **File > Project Structure** and under **Project > SDK** choose **Add SDK > JDK** and the root directory of the installed JDK (not `bin`); set the **Language level** appropriate for the project.
2. Under **Modules > Dependencies > Module SDK**, select **Project SDK** to inherit it or a different JDK for that module; also check **Sources > Language level** if the module needs a different level. Configure the build system's Java version separately if the project uses one: changing the editor's SDK does not replace its configuration.
3. [Inspections](https://www.jetbrains.com/help/idea/code-inspection.html) flag errors and suggestions as you edit: use **Alt+Enter** on a warning to see its explanation or a fix; adjust its severity under **Settings > Editor > Inspections**.

| Shortcut (Windows; default keymap, unverified on this machine) | Use |
|---|---|
| `Alt+Enter` | Context actions and fixes. |
| `Ctrl+Shift+A` | Search for actions and settings. |
| `Ctrl+Alt+L` | Reformat code. |
| `Shift+F10` | Run the current configuration. |
| `Shift+F9` | Debug the current configuration. |

See the [official keymap](https://www.jetbrains.com/help/idea/mastering-keyboard-shortcuts.html): shortcuts may vary with the selected keymap and Windows conflicts.

# Eclipse — workspace, compiler profiles

In [Eclipse IDE](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.user/concepts/concepts-12.htm), the **workspace** is the directory containing preferences and project references; a project can physically reside outside it. Workspace compiler settings serve as defaults; a project can override them ([Java preferences](https://help.eclipse.org/latest/topic/org.eclipse.jdt.doc.user/tasks/task-choose_config_jre.htm)).

1. Under **Window > Preferences > Java > Installed JREs**, add **Standard VM** pointing to the JDK root directory and select it as the workspace default. **Java Runtime Environment** (**JRE**) is the name used by that screen, even when you select a full JDK.
2. For a project, open **Properties > Java Build Path > Libraries** and select the JDK via **JRE System Library**; check **Properties > Java Compiler** and enable project-specific settings to set the compliance level. The compiler level controls syntax/bytecode; it does not itself install or change the JDK used by the project. See the [compiler options](https://help.eclipse.org/latest/topic/org.eclipse.jdt.doc.user/reference/preferences/java/ref-preferences-compiler.htm).

|---|---|

| `Ctrl+Shift+F` | Format code. |
| `Ctrl+1` | Quick fix. |
| `F3` | Go to declaration. |
| `Ctrl+Space` | Complete code. |

See the [Eclipse shortcuts](https://help.eclipse.org/latest/topic/org.eclipse.platform.doc.user/concepts/accessibility/keyboardshortcuts.htm) or **Window > Preferences > General > Keys** to check your active key combination.

# VS Code with Extension Pack for Java

[Visual Studio Code](https://code.visualstudio.com/docs/java/java-tutorial) (VS Code) needs [Extension Pack for Java](https://marketplace.visualstudio.com/items?itemName=vscjava.vscode-java-pack) to provide language, project and debugging support. Open the **project folder**, not just a `.java` file, and wait for import to finish. In a Maven or Gradle project, the build model also determines the Java version: changing the JDK used by the editor alone is not enough ([Java project management](https://code.visualstudio.com/docs/java/java-project)).

1. Run **Java: Configure Java Runtime** from the command palette: check the default JDK and assign one of the detected JDKs to the project. If it is missing, configure it in `java.configuration.runtimes` with the path to its root directory; Maven/Gradle projects also require their own Java configuration to be adjusted.
2. Use the **JAVA PROJECTS** panel to inspect the project and its libraries; suggestions and errors appear in the editor and in **Problems**. See [Java environment configuration](https://code.visualstudio.com/docs/java/java-project#_configure-runtime-for-projects).

| Shortcut (Windows; default keymap, unverified on this machine) | Use |
|---|---|
| `Ctrl+Shift+P` | Open the command palette. |
| `Ctrl+Space` | Code suggestions. |
| `Ctrl+.` | Quick actions. |
| `F12` | Go to definition. |
| `F5` | Start debugging. |

The [keyboard shortcuts editor](https://code.visualstudio.com/docs/getstarted/keybindings) lets you check or change the keys for each action.

**Quick choice:** IntelliJ IDEA if you prioritize integrated navigation and inspections; Eclipse if you work with projects and workspace preferences; VS Code if you prefer a lightweight, extensible editor. In all three, confirm that the project's JDK matches the one required by its build.

To check in PowerShell that the Java executable comes from the same JDK as the compiler (even if another `java` appears earlier in the `PATH` variable):

```bash
$javac = (Get-Command javac.exe).Source # Locate the active compiler
& $javac -version # Show its version
& (Join-Path (Split-Path $javac) 'java.exe') -version # Use the launcher from the same JDK
```
