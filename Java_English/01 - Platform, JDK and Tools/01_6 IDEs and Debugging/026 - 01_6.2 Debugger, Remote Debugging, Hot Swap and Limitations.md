# Debugger, Remote Debugging, Hot swap and limitations

# Debugger — conditional breakpoints, watch, evaluate, step into/over/out

A **breakpoint** pauses a thread at a line to examine the stack and variables. A **conditional** breakpoint pauses only when its expression is true; for example, `i == 3` in a loop. **Watch** displays an expression each time execution stops; **evaluate** computes it at the current pause (avoid calling methods that change state). [Official IntelliJ IDEA debugging guide](https://www.jetbrains.com/help/idea/debugging-code.html).

| Action | Effect while paused |
|---|---|
| Step into | Enters the method called on the line. |
| Step over | Executes the line without entering called methods. |
| Step out | Finishes the current method and returns to its caller. |
| Resume | Continues to the next breakpoint or the end of the program. |

# Remote debugging —  `-agentlib:jdwp`

The [Java Platform Debugger Architecture (JPDA)](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/architecture.html) includes the **Java Debug Wire Protocol (JDWP)**, the protocol between the debugger and the Java Virtual Machine (JVM). The `-agentlib:jdwp` agent enables this communication over the network; [official options](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/conninv.html#vm-invocation-options).

| Option | Meaning |
|---|---|
| `transport=dt_socket` | Uses a network socket. |
| `server=y` / `server=n` | The JVM listens for the debugger / the JVM connects to a listening debugger. |
| `suspend=y` / `suspend=n` | Waits before running `main` until a debugger attaches / starts immediately. |
| `address=127.0.0.1:5005` | Listens only on the local machine, port 5005. |
| `address=*:5005` | Listens on all interfaces: in JDK 9+, the `*` is required to allow external connections; without it, `address=5005` listens only locally ([JPDA connection options](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/conninv.html)). |

**Do not expose JDWP to untrusted networks or enable it in production**: anyone who connects can control execution and evaluate code. For a remote machine, use a protected network/tunnel and restrict access; this exercise listens only on localhost.

Minimal example `DebugDemo.java` (no imports: `String`, `System` and `Thread` are in `java.lang`):

```java
public class DebugDemo {
    public static void main(String[] args) throws InterruptedException {
        for (int i = 0; i < 15; i++) {
            Thread.sleep(500);
            System.out.println(greet("Java"));
        }
    }

    static String greet(String name) {
        return "Hello, " + name;
    }
}
```

In two PowerShell terminals, from the directory where you saved the source, use **the same Java Development Kit (JDK)** for all three executables (adjust `$jdk` to your installation). The loop gives you time to attach the debugger; `-g` retains useful data for inspecting the source code.

```bash
$jdk = 'C:\Program Files\Eclipse Adoptium\jdk-25.0.5.10002-hotspot\bin' # Terminal 1
& "$jdk\javac.exe" -g DebugDemo.java
& "$jdk\java.exe" -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=127.0.0.1:5005 DebugDemo
```

```bash
$jdk = 'C:\Program Files\Eclipse Adoptium\jdk-25.0.5.10002-hotspot\bin' # Terminal 2; while the loop is still running
& "$jdk\jdb.exe" -connect com.sun.jdi.SocketAttach:hostname=127.0.0.1,port=5005
# Inside jdb, before the loop finishes:
stop in DebugDemo.greet
where
cont
exit
```

`where` works **after** the breakpoint stops the thread: it shows `DebugDemo.greet` and its caller. On Windows, `jdb -attach 5005` may select the shared-memory connection by default and fail with `shmemBase_attach failed`; `-connect com.sun.jdi.SocketAttach:...` explicitly selects the socket. To attach from an environment whose default connector is a socket, use `jdb -attach 127.0.0.1:5005` ([jdb manual](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jdb.html)). In an integrated development environment (IDE), create a **Remote JVM Debug** / **Remote Java Application** configuration with host `localhost` and port `5005`, and click **Debug**; do not start the program a second time. Stop the Java process when finished (or wait for the loop to end).

# Hot swap and limitations — which changes the JVM allows without restarting

**Hot swap** replaces a class that is already loaded during a debugging session. Standard class redefinition supports changes to **method bodies** (for example, changing the text returned by `greet`) without restarting; it does not allow adding/removing fields or methods, changing signatures, or modifying the class hierarchy. If you edit `DebugDemo.java`, recompile and ask the IDE to reload the modified classes while the session remains connected; if the change exceeds those limits, restart the process. [Official class redefinition specification](https://docs.oracle.com/en/java/javase/25/docs/api/jdk.jdi/com/sun/jdi/VirtualMachine.html#redefineClasses(java.util.Map)).

# Linux/macOS Commands

On systems where the default `jdb` connector is a socket, `-attach` avoids the explicit connector selection needed on Windows; keep the example's local address.

```bash
jdb -attach 127.0.0.1:5005 # Attaches to the Java process started with JDWP
```
