# Preview and incubator — what they are, how to enable them (--enable-preview --release N, jdk.incubator.* modules)

In **OpenJDK**, provisional features fall into two main categories according to their development stage and stability:

## Preview and incubator
- **Preview features**: **Language or JVM features** that are fully specified and implemented but not yet permanent. Their purpose is to gather community feedback before becoming standard. Enable them with `--enable-preview` together with `--release N` (where N is the exact JDK version containing the feature).

# Feature lifecycle — incubator, preview 1..N, final, deprecation, removal

In the Java ecosystem (OpenJDK), experimental features follow a structured maturation process to ensure feedback before standardization.

Two main provisional states exist: **Preview** (nearly final) and **Incubator** (experimental); features evolve toward standard status or are removed.

### Provisional States and Key Differences
The system distinguishes language features from new APIs through these states:

- **Preview Features**: Fully specified and implemented language or JVM features, but not yet final. They are included directly in the platform, require explicit enablement (--enable-preview), and typically remain in this state for 1–2 releases before becoming standard or being withdrawn.
- **Incubator Modules**: Experimental modules (e.g. jdk.incubator.*) for new APIs or major subsystems. They are less stable, may change API signatures without warning, and live outside the standard namespace to allow rapid iteration without breaking compatibility.

### Progression Toward Finalization or Withdrawal
After the experimental phase, features follow one of these paths:

1. **Standard (Final)**: If it receives positive feedback, the feature becomes a permanent part of the Java SE specification, with no additional flags required.
2. **Deprecation (Deprecated)**: If a better alternative replaces the feature or it is considered obsolete, it enters this state. Although still temporarily supported, its use is discouraged and removal is planned.
3. **Removal**: The final phase, when the feature is completely removed from the product.
- In **Preview/Incubator**, it can be withdrawn directly if feedback is negative or the design fails.
- **Standard** features generally pass through deprecation first before removal in future versions, following compatibility policies.

### Evolution Summary

| State | Nature | Stability | Typical Outcome |
| :--- | :--- | :--- | :--- |
| **Preview** | Nearly final language/JVM feature | Moderate | Standard or Removal |
| **Incubator** | Experimental API/system | Low | Standard, Major Change or Removal |
| **Standard** | Official part of Java | High | Deprecation (long term) |
| **Deprecated** | Obsolete, no longer recommended | Low (limited support) | Removal |
| **Removed** | Removed from the code | N/A | End of life |
