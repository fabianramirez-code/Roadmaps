# Bytecode compilation and execution — source, .class, loading, interpretation and JIT cycle

The **Java execution cycle** begins with compilation to **bytecode**, in which the `javac` compiler transforms source code (`.java`) into a platform-independent intermediate file (`.class`). This **bytecode** is a compact binary format designed for the Java Virtual Machine (JVM), enabling "write once, run anywhere" portability.

During execution, the Class Loader loads the `.class` file into JVM memory, checking its validity and security. The Execution Engine processes this bytecode using a hybrid model combining immediate interpretation (for fast startup) and **Just-In-Time (JIT)** compilation.

The JIT compiler optimizes performance by identifying the most frequently executed code sections (hot spots) and compiling them to native machine code for the specific CPU. This native code is cached for reuse in future calls, outperforming pure interpretation while preserving bytecode's initial portability.

| Phase | Component/Process | Main Action | Result |
| :--- | :--- | :--- | :--- |
| **1. Compilation** | `javac`| Translates source code into JVM instructions. | .class file (bytecode).|              
| **2. Loading** | `Class Loader` | Finds and loads the binary representation into memory. | Classes available in the JVM.|
| **3. Execution** | `Execution Engine` | Interprets bytecode or uses the JIT compiler.| Optimized native code.|
| **4. Optimization** | **JIT** compiler | Converts frequently used code into native machine code.| Maximum runtime performance.|
