# Editions: Java SE, Java EE renamed Jakarta EE, Java ME
## What each covers:
## 1. Java SE (Standard Edition)
- **Purpose:** Development of desktop applications, command-line tools, general backend services and the foundation on which the other editions run.
- **Key components:** The virtual machine (JVM), runtime environment (JRE) and development kit (JDK), plus fundamental APIs (java.lang, java.util, collections, concurrency, networking).
## 2. Jakarta EE (formerly Java EE)
- ***Name change:** Originally owned by Sun Microsystems and then Oracle as Java EE, it passed to the Eclipse Foundation in 2017 and was renamed Jakarta EE because of Oracle's trademark restrictions.*
- **Purpose:** Development of robust enterprise applications, application servers (such as WildFly, Payara, Open Liberty), and microservice-based or enterprise-monolith architectures.
- **Key components:** Standard APIs and specifications such as Jakarta Servlets, Jakarta Persistence (JPA), Jakarta RESTful Web Services (JAX-RS) and Jakarta CDI (Contexts and Dependency Injection).
## 3. Java ME (Micro Edition)
Designed for devices with highly limited memory, processing power and energy.
- **Purpose:** Historically used for embedded systems, smart cards, TV set-top boxes and older mobile phones (feature phones).
- **Current status:** Direct commercial use in mobile phones has become practically obsolete compared with Android, but it remains relevant in specialized IoT (Internet of Things) niches and industrial hardware.
---
## When to choose one or the other:
- Choose Java SE when: You develop command-line tools (CLI), desktop applications, utilities or modern backend services using lightweight frameworks (such as Spring Boot, Quarkus or Micronaut) that run directly on Java SE.
- Choose Jakarta EE when: You build large enterprise monoliths or are required by strict company policies to deploy on a traditional application server (WildFly, Payara).
> **Pragmatic note:** Today, choosing "pure Jakarta EE" on a traditional application server is uncommon for new developments. The current norm is to use Java SE with modern runtimes or frameworks that implement the specifications underneath in embedded form.

> **Key note:** The decisive break occurs in Jakarta EE 9, where all APIs formally migrated their package prefix from `javax.*` to `jakarta.*`.
