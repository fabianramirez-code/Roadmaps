# Release cadence — one release every six months (March and September), JEP 322 (Java 10)

### JEP 322
Introduced in Java 10 (March 2018), a six-month release cadence replaced the previous multi-year model. Under this scheme, feature releases come out every six months, specifically in March and September, with the major version number increasing each cycle.

- Intermediate releases (non-LTS) are supported only until the next release,

- Long-Term Support (LTS) versions are designated more frequently to ensure enterprise stability; Oracle currently designates an LTS every two years (following the 17, 21, 25 series). This model allows features to be delivered predictably and quickly without waiting for a complex project such as Jigsaw to delay an entire release.

# LTS policy — LTS every two years: 8, 11, 17, 21, 25, next 29 (Sep 2027)

Java's Long-Term Support (LTS) policy provides for an LTS release every two years, specifically every fourth general release (released every six months).
> The confirmed LTS releases are Java 8, 11, 17, 21 and 25, and the next LTS is Java 29, expected in September 2027.

Key timeline details:

- **Frequency**: Since Java 17, Oracle has followed a strict schedule designating an LTS release every two years, while intermediate releases (such as Java 26 or 27) have limited support of just six months.
- **Support coverage**: LTS releases receive security patches and updates for an extended period; according to Oracle's schedule, this includes premier and extended support until September 2033 for Java 25 and September 2035 for Java 29.
- **Current recommendation**: Use Java 25 (the latest available LTS) for new projects, and choose an LTS release for production to ensure stability and long-term maintenance.

# JEP / JCP / OpenJDK process — who proposes, who approves, what a JSR is

- **Proposals**: Java Specification Requests (JSRs) are formal proposals submitted by members of the Java Community Process (JCP), including companies and individuals. JDK Enhancement Proposals (JEPs) are proposed by OpenJDK committers and community developers.
- **Approval**: The JCP Executive Committee (EC) is the body that approves and votes on JSRs for standardization. The OpenJDK Lead decides which JEPs are accepted and included in the roadmap for JDK releases.

- **What a JSR is**: A JSR is a formal document defining new specifications, APIs or changes to the Java platform. Each JSR produces an official specification, a Reference Implementation (RI) (usually in OpenJDK) and a Technology Compatibility Kit (TCK) to ensure implementations conform.
