# GraalVM — Graal JIT and native image; the 25.x line follows JDK 25

# GraalVM 25 and the Graal JIT Compiler
- **Version alignment**: Released in September 2025, GraalVM 25 aligns its numbering with JDK 25, integrating all Java 25 features along with performance improvements.
- **Graal JIT compiler**: A Just-In-Time compiler written in Java (rather than C++) that integrates with the JVM through JVMCI (JVM Compiler Interface). This improves maintainability and portability and enables advanced optimizations such as aggressive inlining and sophisticated escape analysis.
- **Consistent architecture**: The 25.x line ensures compatibility between dynamic compilation (JIT) and ahead-of-time compilation (AOT) starting with version 25.0.1.
- **Oracle's strategic change**: Oracle will discontinue support for Graal JIT and Native Image for Java SE Product customers. Future development of these capabilities will move to OpenJDK projects such as Project Leyden, while GraalVM will focus on languages other than Java.

# Native Image (AOT compilation)

This technology compiles Java applications ahead of time (Ahead-Of-Time), producing standalone native executables that do not require a JVM to run.

- Main operation:
  - Closed-world analysis: Traces all code reachable from the main method (points-to analysis) and eliminates dead code, producing smaller binaries.
  - Heap snapshotting: Serializes objects initialized during compilation directly into the executable, achieving millisecond startup times.

- New in the 25.x line:
  - **WP-SCCP**: Conditional constant propagation enabled by default for more precise static analysis and smaller binaries.
  - **XGBoost profiles**: Machine learning used to optimize method selection.
  - **Memory and GC optimization (v25.2)**: Introduction of compressed 32-bit references and cross-platform support for the G1 garbage collector.
  - **LLVM backend (v25.1)**: Addition of an optional backend via `--tool:llvm-backend`.

# Criteria for choosing a distribution — support, update end date, license, TCK certification

Choosing between OpenJDK distributions and Oracle JDK depends mainly on the need for commercial support, the Java version used, and certification requirements.

Key licensing and support differences:

- **OpenJDK (open source)**: Base versions are GPLv2+CE. Free community (upstream) support is very limited (~6 months). For extended support, use third-party distributions such as Eclipse Temurin, Azul Zulu or Red Hat OpenJDK, which offer free or commercial security updates until dates later than Oracle's.
- **Oracle JDK (commercial)**: A closed, TCK-certified distribution. Production use requires an Oracle Java SE Universal Subscription after an initial free period (currently until September 2026 for LTS version 21). Without a subscription, the OTN license applies (development/personal use only).

Selection criteria and end-of-life dates (LTS) — base the decision on the selected LTS version and the availability of security patches:

### TCK Certification and Recommendations

- **TCK certification**: Only Oracle JDK and verified distributions such as Eclipse Temurin (Adoptium) or Red Hat OpenJDK pass the Technology Compatibility Kit, ensuring standards compatibility. Unverified versions might not comply with the Java SE specification.
- **Recommendation**: For production environments without a budget for Oracle licenses, use Eclipse Temurin or Azul Zulu (LTS versions). For companies with Oracle subscriptions or needing guaranteed commercial support, Oracle JDK or Red Hat OpenJDK are the most robust choices. Avoid non-LTS versions (such as Java 24 or 26) in production because their lifecycle is only 6 months.
