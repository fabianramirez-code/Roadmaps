# Mastery Questions, Practice and Common Mistakes

# Mastery Questions

1. What is the difference between JDK, JRE and JVM, and what is installed in production today?
2. When is the next LTS release, and what is the release cycle?
3. What does preview mean, and how do you compile and run code using a preview feature?
4. How do Oracle JDK, Temurin and Corretto differ in licensing and support?
5. What does `--release 17` do that `-source 17 -target 17` does not?
6. How do you run a `.java` file without explicitly compiling it, and since which version?
7. What is the difference between the classpath and the module path?
8. What does an executable JAR contain, and how does it declare its main class?
9. What are `jlink` and `jpackage` for, and how do they differ?
10. How do you inspect a class's bytecode?
11. How do you switch JDKs in a session without changing system variables?
12. What is a JEP, and who approves it?

## Practice

1. Install JDK 8, 17 and 25 with [[Scoop]] or [[Jabba]] and switch between them.
2. Compile a "Hello world" with `javac`, package it with `jar` and run it with `-jar`.
3. Run a single source file and a multi-file program on JDK 25.
4. Disassemble a `for` loop and a `switch` using `javap -c`.
5. Use `jshell` to try `List.of`, `var` and text blocks.
6. Create a minimal runtime with `jlink` and measure its size.
7. Generate an installer with `jpackage`.
8. Debug a program with a conditional breakpoint in IntelliJ IDEA.

## Common Mistakes

- Confusing the version of `java` with that of `javac` because of an incorrectly ordered `PATH`.
- Compiling with a newer JDK without `--release` and running on an older JRE (`UnsupportedClassVersionError`).
- Using a JRE/JDK without `JAVA_HOME` in build tools.
- Assuming `-source/-target` validates available APIs (it does not; `--release` does).
- Enabling preview in production.
- Mixing the classpath and module path without understanding automatic modules.
- Choosing a distribution without checking when free support ends.
- Ignoring `java -Xlog` and `jcmd` when diagnosing problems.

### Answers

1. **JDK, JRE and JVM; production.** The Java Virtual Machine (JVM) executes bytecode; the Java Runtime Environment (JRE) adds the libraries needed to run it; the Java Development Kit (JDK) adds development tools.
   Today, the JDK is installed or an application-specific runtime image is distributed; a separate JRE is not assumed (notes 003 and 018).

2. **Next LTS and release cycle.** Java 25 is the current Long-Term Support (LTS) release, published on September 16, 2025; Java 29 is planned for September 2027.
   A release comes every six months (March and September) and, since Java 17, an LTS release every two years (note 006; Java 00 - Index).

3. **Preview: compilation and execution.** A *preview* feature is specified but not yet final; it requires explicit enabling and may change (note 007).
   With the JDK for version N: `javac --enable-preview --release N File.java` (or `--source N` instead of `--release N`); run it with `java --enable-preview File`. N must match the JDK version that includes the feature.

4. **Oracle JDK, Temurin and Corretto.** Oracle JDK permits free production use under the No-Fee Terms and Conditions (NFTC) for a limited period; check the license and end date before upgrading.
   Temurin and Corretto are OpenJDK distributions under GPLv2 with the Classpath exception: Temurin provides community updates; Amazon maintains Corretto with free long-term updates (notes 001, 008 and 011).

5. **`--release 17` versus `-source 17 -target 17`.** `javac --release 17` fixes the syntax, bytecode and programming interfaces available in Java 17.
   `-source` and `-target` fix the syntax and bytecode, but may allow calls to later libraries present in the current JDK to compile: the program would fail on Java 17 (note 015).

6. **Source file without explicit compilation.** Since Java 11, `java File.java` compiles in memory and runs the file without leaving a `.class` in the directory (note 015).
   Since Java 22, it can also locate other required source files when launching the main file (note 016).

7. **Classpath and module path.** The *classpath* searches directories and Java Archive (JAR) files for classes, in order; its classes belong to the unnamed module.
   The *module path* resolves modules: their descriptors declare dependencies with `requires` and visibility with `exports`; a JAR without a descriptor can act as an automatic module (note 023).

8. **Executable JAR and main class.** It contains classes and resources, as well as `META-INF/MANIFEST.MF`; the manifest declares `Main-Class: package.Class` with the fully qualified name of the class containing `main`.
   It can then be launched with `java -jar app.jar`; external dependencies can be declared with `Class-Path` in the manifest (notes 016 and 024).

9. **`jlink` versus `jpackage`.** `jlink` builds a reduced runtime image with the required modules, not an installer.
   `jpackage` packages the application and its runtime as an application image or native installer; it can reuse the image created by `jlink` (note 018).

10. **Bytecode inspection.** Compile the class and use `javap -c Class` to see the disassembled instructions of its methods; `-v` adds details and `-p` shows private members.
    This inspects the `.class`; it does not recover the original source code (note 017).

11. **Switch JDKs only for the session.** In PowerShell, set `$env:JAVA_HOME` to the chosen JDK directory and prepend `$env:JAVA_HOME\bin` to `$env:Path`; do not change persistent variables.
    Alternatively, Jabba on Windows or Software Development Kit Manager (SDKMAN) on Linux, macOS or Windows Subsystem for Linux allow switching versions per session; check that `java` and `javac` come from the same JDK (notes 012 and 013).

12. **JEP and approval.** A JDK Enhancement Proposal (JEP) is a numbered proposal for a JDK improvement in OpenJDK, not a Java Specification Request (JSR) of the Java Community Process (JCP).
    Exactly who approves it and its inclusion in a release remains **unverified**: consult [JEP 1](https://openjdk.org/jeps/1) and [JEP 2](https://openjdk.org/jeps/2) before assigning that responsibility to a specific person or body (note 006).
