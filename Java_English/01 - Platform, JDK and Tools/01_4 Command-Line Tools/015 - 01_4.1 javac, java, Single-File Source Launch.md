# javac, java, Single-File Source Launch

## javac

**Compiler**: converts `.java` to `.class` (bytecode).

| Command | What it does |
|---|---|
| `javac Test.java` | Generates `Test.class` beside the source |
| `javac -d out Test.java` | `-d`: directory where `.class` files are **written** (creates it if absent) |
| `javac -cp lib\x.jar Test.java` | `-cp`: where to **look for** compiled classes (classpath); separator `;` |
| `javac --release 17 Test.java` | Java 17 bytecode **and** API; rejects later APIs |
| `javac -Xlint:all Test.java` | All warnings (`-Xlint:deprecation`, `-Xlint:unchecked`) |
| `javac -parameters Test.java` | Stores parameter names in `.class` (reflection: Spring, Jackson) |

> `--release` replaces `-source` + `-target`: those only change bytecode, not API validation.

> A `.jar` is a ZIP containing `.class` files, resources and `META-INF/MANIFEST.MF`.

## java

**Launcher**: starts the Java Virtual Machine (JVM) and runs compiled code. Takes a **class** name (`Test`), not a filename.

| Mode | Command | Dependencies via |
|---|---|---|
| Class | `java -cp out Test` | `-cp` |
| Packaged class | `java -cp "out;lib\x.jar" app.Main` | `-cp` |
| JAR | `java -jar app.jar` | Manifest `Class-Path` (ignores `-cp`) |
| Module | `java -p mods -m module/package.Main` | `-p` (module path) |

## Workflow: `-d` and `-cp`

These commands are **alternatives**, not a sequence. Rule: `-d` chooses where to write, `-cp` where to search.

The examples are in `Examples_015`; run the commands there:

```bash
cd Examples_015
```

`lib\` and `out\` are relative to that directory.

```bash
javac Test.java              # Test.class beside the source
java Test                    # OK: searches the current directory

javac -d out Test.java       # out\Test.class
java Test                    # ERROR: the .class is in out\
java -cp out Test            # OK
```

### With a dependency (.jar)

```bash
curl.exe -L -o lib\commons-lang3.jar https://repo1.maven.org/maven2/org/apache/commons/commons-lang3/3.17.0/commons-lang3-3.17.0.jar
```

`Test.java`:

```java
import org.apache.commons.lang3.StringUtils;

public class Test {
    public static void main(String[] args) {
        System.out.println(StringUtils.capitalize("hello world!"));
    }
}
```

```bash
javac -cp lib\commons-lang3.jar -d out Test.java  # Write to out
javac -cp lib\commons-lang3.jar Test.java         # Write beside the source
java -cp "out;lib\commons-lang3.jar" Test         # prints: Hello world!
java -cp ".;lib\commons-lang3.jar" Test           # Test.class in current directory (.)
```

> `-cp` **replaces** the default classpath (`.`), rather than extending it. If you use `-cp`, the current directory is searched only if you include `.`. Without it, `java -cp lib\commons-lang3.jar Test` produces `ClassNotFoundException`. A leading `\` (`\lib\...`) points to the drive root.

The JAR is needed at **both** stages. Without it:

| Command | Error |
|---|---|
| `javac -d out Test.java` | `package org.apache.commons.lang3 does not exist` |
| `java -cp out Test` | `NoClassDefFoundError` |

## Single-file source launch

Since Java 11 (JEP 330): compiles in memory and runs without generating `.class`.

> **JEP** (JDK Enhancement Proposal): a proposal for a JDK change in OpenJDK; listed at https://openjdk.org/jeps/. **JEP 330** ("Launch Single-File Source-Code Programs") enables `java Test.java`.

```bash
java Test.java                                      # compile + run
java Test.java arg1 arg2                            # arguments after the file belong to the program
java -cp ".;lib\commons-lang3.jar" Test.java        # dependency: -cp precedes the file
```

- Runs the `main` of the **first class** in the file.
- Only for experiments and scripts.

# Linux/macOS Commands

Paths (`/`) and the classpath separator (`:` rather than `;`) differ.

```bash
cd Examples_015
javac -cp lib/commons-lang3.jar -d out Test.java
java -cp out:lib/commons-lang3.jar Test
```
