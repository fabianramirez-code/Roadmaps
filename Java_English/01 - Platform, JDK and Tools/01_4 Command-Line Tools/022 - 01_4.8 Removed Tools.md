# Removed Tools

# `javah` (removed in 10), `jjs`/Nashorn (removed in 15, JEP 372), Pack200 (removed in 14, JEP 367)

A JDK Enhancement Proposal (JEP) is a [numbered OpenJDK improvement proposal](https://openjdk.org/jeps/0). These tools are no longer part of the Java Development Kit (JDK):

| Tool | What it did | Removed in | Alternative |
|---|---|---|---|
| `javah` | Generated headers for the Java Native Interface (JNI), used to call native code from Java. | Java 10 ([JEP 313](https://openjdk.org/jeps/313)) | [`javac -h`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html) generates those headers; for new native code bindings, consider the [Foreign Function & Memory API (FFM)](https://openjdk.org/jeps/454), finalized in Java 22. |
| `jjs` / Nashorn | Ran JavaScript through the `jjs` interpreter or Nashorn engine on the Java Virtual Machine (JVM). | Java 15 ([JEP 372](https://openjdk.org/jeps/372)) | Use an external engine such as [GraalJS (GraalVM JavaScript)](https://www.graalvm.org/latest/reference-manual/js/) or run JavaScript outside the JVM. |
| `pack200` / `unpack200` (Pack200) | Compressed and decompressed Java Archive (JAR, packaged class and resource) files in a special format. | Java 14 ([JEP 367](https://openjdk.org/jeps/367)) | Standard compression with [`jar`/ZIP](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jar.html); for runtime images, `jlink --compress` (note 018). |

To try the `javah` alternative, create `Test.java` with a `native` method (implemented in native code) in your examples directory; no imports are required:

```java
public class Test {
    public native void greet();
}
```

```bash
javac -h headers -d classes Test.java # Generates headers\Test.h and classes\Test.class
```

On the tested JDK 25, `javah`, `jjs`, `pack200` and `unpack200` appear neither in `PATH` nor in the JDK's `bin` directory; the compilation above generated `Test.h` with declaration `Java_Test_greet`. No Linux/macOS command section is necessary: `javac -h` is used the same way.
