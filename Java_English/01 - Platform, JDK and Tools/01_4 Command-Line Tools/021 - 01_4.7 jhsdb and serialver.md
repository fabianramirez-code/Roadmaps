# jhsdb and serialver — occasional uses

## jhsdb — exceptional diagnostics

[`jhsdb`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jhsdb.html) uses HotSpot's Serviceability Agent (SA), HotSpot being the Java Virtual Machine (JVM) implementation included in this Java Development Kit (JDK). It can analyze a live process or, after a crash, a process memory dump (*core dump*). Use `jcmd` (note 019) for routine diagnostics; reserve `jhsdb` for advanced cases such as a hung or crashed JVM. **Attaching to a live process pauses it during analysis** and requires sufficient permissions: assess the impact first.

Main modes: `clhsdb` (interactive console), `hsdb` (graphical interface), `debugd` (remote server, deprecated in JDK 25), `jstack` (threads), `jmap` (memory), `jinfo` (options and properties) and `jsnap` (counters). `--pid <pid>` selects a live process; for a dump, `--core <file>` **must be accompanied by** `--exe <executable>` for that process. Dumps and properties may contain sensitive information.

For a local test, reuse `Wait.java` and the method of finding its process identifier (PID) from note 019: leave it running in one terminal and replace `<pid>` with the number found in another. Stop `Wait` with Ctrl+C afterwards. On this Windows JDK 25, the thread query could attach; core dump analysis and other modes were not tested on a process.

```bash
jhsdb jstack --pid <pid> # Displays thread traces while pausing the process
```

## serialver — serialization version identifier

[`serialver`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/serialver.html) computes the default `serialVersionUID` for a class implementing `Serializable` (the [object serialization](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/serial-arch.html) interface). Create `Message.java` in `Examples_021` with this minimal example:

```java
import java.io.Serializable;

public class Message implements Serializable {
    private String text;
}
```

```bash
javac -d classes Message.java        # Compiles class
serialver -classpath classes Message # Prints calculated declaration
```

If the class is in the current classpath directory, `serialver Class` suffices (for example, `serialver Message`). Copy the resulting value and declare `private static final long serialVersionUID = <value>L;` **inside the class** when maintaining its serialized format: a compatible modification will then not accidentally change the computed identifier and prevent reading objects written by an older version. The identifier alone does not guarantee that all field changes are compatible.

**When to use it in practice**

1. **Already deployed class without a declared identifier:** if objects have been saved (files, caches, sessions or queues) and you must change it, run `serialver` on the compiled old version. Java derives the identifier from class structure; a change might alter it and make old data unreadable.
2. **Two versions that must communicate:** for example, client and server with different versions of the class. They share the identifier and deserialization determines whether changes allow reading the data.
3. **Diagnostics:** an `InvalidClassException` displays both conflicting identifiers. `serialver` reveals which one each compiled version produces and helps locate the class change.

**When it is unnecessary**

- For a new class, you can declare a value such as `1L` without the tool.
- Many modern projects do not use native Java serialization (`Serializable`): they prefer [JavaScript Object Notation (JSON, data interchange format)](https://www.json.org/json-es.html), [Protocol Buffers (structured data interchange format)](https://protobuf.dev/overview/) or [Apache Avro (data serialization format)](https://avro.apache.org/docs/current/), which do not rely on this identifier.
- Native deserialization of untrusted data has security risks; it is therefore avoided in new code.
