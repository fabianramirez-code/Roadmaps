# jcmd, jps, jstack, jmap, jstat, jinfo, jfr and jconsole-jvisualvm

# jcmd — general-purpose JVM diagnostic command

The Java Virtual Machine (JVM) runs the program. [`jcmd`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jcmd.html) lets you query and diagnose a local JVM; run the tools as the same user who started the process. Some operations, such as a heap dump, consume time and disk space: use them carefully.

To try **all** commands in this note, create `Wait.java` in `Examples_019` (do not create files from the note). The thread named `worker` stays waiting; leave the first terminal open while inspecting the process in another:

```java
import java.util.concurrent.TimeUnit;

public class Wait {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                try {
                    TimeUnit.SECONDS.sleep(1);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }
        }, "worker");
        worker.start();
        worker.join();
    }
}
```

```bash
javac Wait.java
java Wait                           # First terminal: stop with Ctrl+C when finished
```

In the second terminal, also in `Examples_019`, identify the process identifier (PID), the number identifying the process; **replace** `<pid>` with that number in the following commands. Syntax: `jcmd <pid> <command>`; without arguments it lists the same Java processes as the listing option. `help` queries the commands available **in that JVM**.

A heap dump and starting a Java Flight Recorder (JFR) recording, the JVM's event recorder, can cause pauses or performance overhead and consume time and space. A heap dump may contain sensitive data; system properties and recordings can too: inspect them before sharing.

```bash
jcmd -l                                               # Lists Java processes (same as no arguments)
jcmd <pid> help                                       # Commands supported by this JVM
jcmd <pid> VM.version                                 # Version
jcmd <pid> VM.flags                                   # Startup options and configuration
jcmd <pid> VM.system_properties                       # System properties
jcmd <pid> VM.uptime                                  # Uptime
jcmd <pid> Thread.print                               # Thread state and traces; inspect deadlocks
jcmd <pid> GC.heap_info                               # Memory summary
jcmd <pid> GC.run                                     # Requests Garbage Collection (GC)
jcmd <pid> GC.heap_dump heap.hprof                    # Heap dump to a potentially large file
jcmd <pid> JFR.start name=study                       # Starts recording
jcmd <pid> JFR.dump name=study filename=recording.jfr # Saves recording
jcmd <pid> JFR.stop name=study                        # Stops recording
```

# jps, jstack, jmap, jstat, jinfo — basic diagnostics

These Java Development Kit (JDK) tools offer specific queries; [`jcmd`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jcmd.html) covers almost all of them and is usually the first choice. See the manuals for [`jps`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jps.html), [`jstack`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jstack.html), [`jmap`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jmap.html), [`jstat`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jstat.html) and [`jinfo`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jinfo.html).

Histogram and dump queries with `jmap` may also cause pauses or overhead; follow the time, space and sensitive-data precautions above.

```bash
jps -l                                         # Identifiers and full class or Java Archive (JAR, packaged classes) names
jps -v                                         # JVM arguments
jstack <pid>                                  # Thread states and traces; reports deadlocks at end
jmap -histo <pid>                              # Object histogram
jmap -dump:format=b,file=heap.hprof <pid>      # Binary dump; rename if file already exists
jstat -gc <pid> 1s 2                          # Two samples one second apart: GC capacity and activity
jstat -gcutil <pid> 1s 2                      # Two samples one second apart: percentage occupancy
jinfo -flags <pid>                            # JVM options
jinfo -sysprops <pid>                         # System properties (may contain sensitive data)
```

# jfr and jconsole/jvisualvm (the latter is no longer in the JDK)

[`jfr`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jfr.html) **reads** the `recording.jfr` file created earlier; check recordings for sensitive data before sharing. [`jconsole`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jconsole.html) remains in the JDK and provides graphical monitoring: run it and select `Wait`. [VisualVM](https://visualvm.github.io/) is an independent project: `jvisualvm` has not shipped with the JDK since Java 9; install it separately.

```bash
jfr summary recording.jfr                             # Summary and event counts; file created above
jfr view all-events recording.jfr                     # Event table (can be long)
jfr print --events jdk.JVMInformation recording.jfr   # JVM information events, if present
jconsole                                             # Opens graphical UI to connect to local process
```

# Linux/macOS Commands

The preceding console commands do not change; `jconsole` cannot open on systems without a graphical desktop. Local diagnostics may also be restricted by system permissions.
