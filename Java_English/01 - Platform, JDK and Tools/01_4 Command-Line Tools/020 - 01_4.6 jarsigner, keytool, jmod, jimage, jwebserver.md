# jarsigner, keytool, jmod, jimage, jwebserver

# jarsigner, keytool — signing and keystores

[`keytool`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/keytool.html) **creates and inspects keys and certificates in a keystore; [`jarsigner`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jarsigner.html) signs and verifies Java Archive (JAR) files containing classes and resources**. Public-Key Cryptography Standards #12 (PKCS12) is a password-protected [keystore format](https://www.rfc-editor.org/rfc/rfc7292). This example's **self-signed** certificate is only for testing: it does not establish identity to third parties. Do not version keystores or passwords; in real use let the tools **prompt for the password** rather than passing it on the command line (which may remain in history or be visible to other processes).

Work in `Examples_020`: reuse `Test.java` from note 017 and its minimal JAR (`myapp.jar`), compiling and packaging it here with that note's commands. For the test certificate, supply the details requested by `keytool`; `-dname` skips identity questions, **not** the password prompt. Rivest–Shamir–Adleman (RSA) is the [key algorithm](https://docs.oracle.com/en/java/javase/25/docs/specs/security/standard-names.html#keypairgenerator-algorithms) chosen here.

```bash
keytool -genkeypair -alias test -keyalg RSA -keysize 2048 -validity 30 -keystore tests.p12 -storetype PKCS12 -dname "CN=Test" # Prompts for password; creates self-signed certificate valid for 30 days
keytool -list -keystore tests.p12 -storetype PKCS12 # Displays entries
keytool -exportcert -alias test -keystore tests.p12 -storetype PKCS12 -file test.cer # Exports only public certificate
jarsigner -keystore tests.p12 -storetype PKCS12 -signedjar Test-signed.jar myapp.jar test # Signs a copy of the JAR
jarsigner -verify Test-signed.jar # Verifies signature; warns about self-signed certificate
```

## Checking results

Inspect the certificate and signed entries. On the tested JDK 25, `keytool` failed with `MissingFormatArgumentException` when displaying certificates in Spanish; `-J-Duser.language=en` avoids that failure (the keystore password is requested when querying):

```bash
keytool -J-Duser.language=en -list -v -keystore tests.p12 -storetype PKCS12 # Alias test, CN=Test, 30-day validity and SHA-256 fingerprint
keytool -J-Duser.language=en -printcert -file test.cer # Same SHA-256 fingerprint as keystore
jarsigner -verify -verbose -certs Test-signed.jar # Lists entries and signer's certificate
jar tf Test-signed.jar # Includes META-INF/TEST.SF and META-INF/TEST.RSA (derived from alias)
```

Verification prints `jar verified.` and warns about the self-signed certificate, as expected for this test. To check integrity, copy the signed JAR, **change the text of `Test.java` and recompile `Test.class`** before replacing that signed entry:

```bash
Copy-Item Test-signed.jar Tampered.jar # Keeps original
javac Test.java # After changing the text, generates a different class
jar uf Tampered.jar Test.class # Replaces signed entry
jarsigner -verify Tampered.jar # Fails: jarsigner error: java.lang.SecurityException: SHA-384 digest error for Test.class (exit code 1)
```

Adding a new unsigned entry **does not** cause that failure: `jarsigner -verify` may print `jar verified.` with an unsigned-entry warning.

# jmod, jimage — internal module formats

[`jmod`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jmod.html) packages module classes in a Java Module (JMOD) file for `jlink`; **a JMOD cannot run directly at runtime**. To try it, create a minimal `module-info.java` in `Examples_020` (do not include `Test.class` from note 017: it is in the unnamed package, which a module cannot contain):

```java
module example.module {
}
```

```bash
javac -d classes module-info.java # Compiles descriptor
jmod create --class-path classes example.module.jmod # Packages module
jmod list example.module.jmod # Lists entries
jmod describe example.module.jmod # Shows descriptor and dependencies
jmod extract --dir extracted example.module.jmod # Extracts classes\module-info.class
```

[`jimage`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jimage.html) inspects a runtime's `lib\modules` module image, either from the installed Java Development Kit (JDK) or an image created with `jlink`. If `JAVA_HOME` points to the JDK, these commands limit extraction to one class; without `--include`, `extract` would unpack **the entire** image:

```bash
$image = Join-Path $env:JAVA_HOME 'lib\modules' # Installed JDK path
jimage list --include 'glob:**/java/lang/Object.class' $image # Lists selected class
jimage info $image # Image header
jimage extract --dir extracted-image --include 'glob:**/java/lang/Object.class' $image # Extracts only that class
```

# jwebserver — Simple Web Server (Java 18+, JEP 408)

[`jwebserver`](https://openjdk.org/jeps/408) serves **static files** via GET and HEAD requests (content and headers, respectively). For tests and prototypes, **not production**; serve only a prepared directory with files safe to display, not the entire project. The same proposal includes a programming interface for simple Java servers.

| Option | Function |
|---|---|
| `-p 8000` | Listening port. |
| `-d web` | Directory of served files. |
| `-b 127.0.0.1` | Local address: accessible only on this computer. |
| `-o info` | Output verbosity (`none`, `info` or `verbose`). |

After placing `index.html` in the `web` directory under `Examples_020`, keep the first terminal open; query from a second terminal in that directory and stop the server with Ctrl+C:

```bash
jwebserver -p 8000 -d web -b 127.0.0.1 -o info # First terminal
Invoke-WebRequest http://127.0.0.1:8000/ # Second terminal: requests index
```

# Linux/macOS Commands

Only the request from the second terminal differs (if PowerShell is unavailable); use `/` when inspecting extracted paths:

```bash
curl http://127.0.0.1:8000/ # Checks response
```
