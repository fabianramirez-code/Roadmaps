# Preguntas de dominio, prácticas y errores comunes

# Preguntas de dominio

1. ¿Qué diferencia hay entre JDK, JRE y JVM y qué se instala hoy en producción?
2. ¿Cuándo sale la próxima versión LTS y cuál es el ciclo?
3. ¿Qué significa preview y cómo se compila y ejecuta código con una característica preview?
4. ¿Qué diferencia hay entre Oracle JDK, Temurin y Corretto en licencia y soporte?
5. ¿Qué hace `--release 17` que no hace `-source 17 -target 17`?
6. ¿Cómo se ejecuta un archivo `.java` sin compilar explícitamente y desde qué versión?
7. ¿Qué diferencia hay entre classpath y module path?
8. ¿Qué contiene un JAR ejecutable y cómo declara su clase principal?
9. ¿Para qué sirven `jlink` y `jpackage` y qué los diferencia?
10. ¿Cómo se inspecciona el bytecode de una clase?
11. ¿Cómo se cambia de JDK en una sesión sin tocar variables del sistema?
12. ¿Qué es un JEP y quién lo aprueba?

## Prácticas

1. Instalar JDK 8, 17 y 25 con [[Scoop]] o [[Jabba]] y alternar entre ellos.
2. Compilar un "Hola mundo" con `javac`, empaquetarlo con `jar` y ejecutarlo con `-jar`.
3. Ejecutar un archivo fuente único y uno multi-archivo en JDK 25.
4. Desensamblar con `javap -c` un bucle `for` y un `switch`.
5. Usar `jshell` para probar `List.of`, `var` y text blocks.
6. Crear un runtime mínimo con `jlink` y medir su tamaño.
7. Generar un instalador con `jpackage`.
8. Depurar un programa con un breakpoint condicional en IntelliJ IDEA.

## Errores comunes

- Confundir la versión de `java` con la de `javac` por un `PATH` mal ordenado.
- Compilar con JDK nuevo sin `--release` y ejecutar en un JRE antiguo (`UnsupportedClassVersionError`).
- Usar un JRE/JDK sin `JAVA_HOME` en herramientas de build.
- Asumir que `-source/-target` valida la API disponible (no lo hace; `--release` sí).
- Habilitar preview en producción.
- Mezclar classpath y module path sin entender los módulos automáticos.
- Elegir una distribución sin revisar el fin de soporte gratuito.
- Ignorar `java -Xlog` y `jcmd` al diagnosticar.

### Respuestas

1. **JDK, JRE y JVM; producción.** Java Virtual Machine (JVM) ejecuta bytecode; Java Runtime Environment (JRE) añade las bibliotecas para ejecutarlo; Java Development Kit (JDK) añade herramientas de desarrollo.
   Hoy se instala el JDK o se distribuye una imagen de ejecución específica de la aplicación, no se presupone un JRE separado (notas 003 y 018).

2. **Próxima LTS y ciclo.** Java 25 es la versión de soporte a largo plazo (Long-Term Support, LTS) actual, publicada el 16 de septiembre de 2025; Java 29 está prevista para septiembre de 2027.
   Sale una versión cada seis meses (marzo y septiembre) y, desde Java 17, una LTS cada dos años (nota 006; Java 00 - Índice).

3. **Preview: compilación y ejecución.** Una característica *preview* está especificada, pero aún no es definitiva; requiere habilitación explícita y puede cambiar (nota 007).
   Con el JDK de la versión N: `javac --enable-preview --release N Archivo.java` (o `--source N` en vez de `--release N`); ejecuta con `java --enable-preview Archivo`. N debe corresponder a la versión del JDK que incorpora esa característica.

4. **Oracle JDK, Temurin y Corretto.** Oracle JDK permite uso gratuito en producción bajo No-Fee Terms and Conditions (NFTC) durante una ventana limitada; consulta la licencia y la fecha de fin antes de actualizar.
   Temurin y Corretto son distribuciones de OpenJDK bajo GPLv2 con excepción Classpath: Temurin ofrece actualizaciones comunitarias; Amazon mantiene Corretto con actualizaciones gratuitas a largo plazo (notas 001, 008 y 011).

5. **`--release 17` frente a `-source 17 -target 17`.** `javac --release 17` fija sintaxis, bytecode y las interfaces de programación disponibles en Java 17.
   `-source` y `-target` fijan sintaxis y bytecode, pero pueden dejar compilar llamadas a bibliotecas posteriores presentes en el JDK actual: el programa fallaría en Java 17 (nota 015).

6. **Archivo fuente sin compilación explícita.** Desde Java 11, `java Archivo.java` compila en memoria y ejecuta el archivo sin dejar un `.class` en el directorio (nota 015).
   Desde Java 22 también puede localizar otros fuentes necesarios al lanzar el archivo principal (nota 016).

7. **Classpath y module path.** El *classpath* busca clases en directorios y archivos Java Archive (JAR), por orden; sus clases pertenecen al módulo sin nombre.
   El *module path* resuelve módulos: sus descriptores declaran dependencias con `requires` y visibilidad con `exports`; un JAR sin descriptor puede actuar como módulo automático (nota 023).

8. **JAR ejecutable y clase principal.** Contiene clases y recursos, además de `META-INF/MANIFEST.MF`; el manifiesto declara `Main-Class: paquete.Clase` con el nombre completo de la clase que tiene `main`.
   Así se lanza con `java -jar app.jar`; las dependencias externas se pueden declarar con `Class-Path` en el manifiesto (notas 016 y 024).

9. **`jlink` frente a `jpackage`.** `jlink` construye una imagen de ejecución reducida con los módulos requeridos, no un instalador.
   `jpackage` empaqueta la aplicación y su entorno de ejecución como imagen de aplicación o instalador nativo; puede reutilizar la imagen creada por `jlink` (nota 018).

10. **Inspección del bytecode.** Compila la clase y usa `javap -c Clase` para ver las instrucciones desensambladas de sus métodos; `-v` añade detalles y `-p` muestra miembros privados.
    Se inspecciona el `.class`, no se recupera el código fuente original (nota 017).

11. **Cambiar de JDK solo en la sesión.** En PowerShell, asigna `$env:JAVA_HOME` a la carpeta del JDK elegido y antepón `$env:JAVA_HOME\bin` a `$env:Path`; no cambies las variables persistentes.
    Alternativamente, Jabba en Windows o Software Development Kit Manager (SDKMAN) en Linux, macOS o Windows Subsystem for Linux permiten cambiar de versión por sesión; comprueba que `java` y `javac` procedan del mismo JDK (notas 012 y 013).

12. **JEP y aprobación.** Una JDK Enhancement Proposal (JEP) es una propuesta numerada de mejora del JDK en OpenJDK, no una Java Specification Request (JSR) del Java Community Process (JCP).
    La atribución exacta de su aprobación y de su inclusión en un release queda **sin verificar**: consultar [JEP 1](https://openjdk.org/jeps/1) y [JEP 2](https://openjdk.org/jeps/2) antes de asignar esa responsabilidad a una persona u órgano concreto (nota 006).
