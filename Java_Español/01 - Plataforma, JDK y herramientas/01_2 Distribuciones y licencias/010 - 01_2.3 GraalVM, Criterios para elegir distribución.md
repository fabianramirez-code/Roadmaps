# GraalVM — JIT Graal y native image; la línea 25.x sigue a JDK 25

# GraalVM 25 y el Compilador JIT Graal
- **Alineación de Versiones**: Lanzado en septiembre de 2025, GraalVM 25 sincroniza su numeración con JDK 25, integrando todas las novedades de Java 25 junto con mejoras de rendimiento.
- **Compilador Graal JIT**: Es un compilador Just-In-Time escrito en Java (en lugar de C++) que se integra con la JVM mediante JVMCI (JVM Compiler Interface). Esto mejora su mantenibilidad, portabilidad y permite optimizaciones avanzadas como el inlineo agresivo y análisis de escapes sofisticados.
- **Arquitectura Coherente**: La línea 25.x garantiza compatibilidad entre la compilación dinámica (JIT) y la compilación anticipada (AOT) a partir de la versión 25.0.1.
- **Cambio Estratégico de Oracle**: Oracle discontinuará el soporte de Graal JIT y Native Image para clientes de Java SE Product. El desarrollo futuro de estas capacidades se trasladará a proyectos de OpenJDK como Project Leyden, mientras que GraalVM se enfocará en lenguajes distintos a Java.

# Native Image (Compilación AOT)

Es la tecnología que compila aplicaciones Java por adelantado (Ahead-Of-Time) generando ejecutables nativos autónomos que no requieren una JVM para funcionar.

- Funcionamiento Principal:
  - Análisis de Mundo Cerrado: Rastrea todo el código alcanzable desde el método main (points-to analysis) y elimina el código muerto, logrando binarios más ligeros.
  - Heap Snapshotting: Serializa los objetos inicializados durante la compilación directamente en el ejecutable, logrando tiempos de arranque en milisegundos.

- Novedades en la línea 25.x:
  - **WP-SCCP**: Propagación condicional de constantes activada por defecto para un análisis estático más preciso y binarios más pequeños.
  - **Perfiles con XGBoost**: Uso de aprendizaje automático para optimizar la selección de métodos.
  - **Optimización de Memoria y GC (v25.2)**: Introducción de referencias comprimidas de 32 bits y soporte multiplataforma para el recolector de basura G1 GC.
  - **Backend LLVM (v25.1)**: Inclusión de un backend opcional mediante `--tool:llvm-backend`.

# Criterios para elegir distribución — soporte, fecha de fin de actualizaciones, licencia, certificación TCK

La elección entre distribuciones de OpenJDK y Oracle JDK depende principalmente de la necesidad de soporte comercial, la versión de Java utilizada y los requisitos de certificación.

Diferencias clave en licencia y soporte:

- **OpenJDK (Código Abierto)**: Las versiones base son GPLv2+CE.  El soporte gratuito de la comunidad (Upstream) es muy limitado (~6 meses).  Para soporte extendido, se deben usar distribuciones de terceros como Eclipse Temurin, Azul Zulu o Red Hat OpenJDK, que ofrecen actualizaciones de seguridad gratuitas o comerciales hasta fechas posteriores a las de Oracle.
- **Oracle JDK (Comercial)**: Es una distribución TCK-certificada y cerrada. El uso en producción requiere licencia Oracle Java SE Universal Subscription después de una ventana gratuita inicial (actualmente hasta septiembre de 2026 para la versión LTS 21).  Sin suscripción, se aplica la licencia OTN (solo desarrollo/personal).

Criterios de elección y fechas de fin de vida (LTS) — La decisión debe basarse en la versión LTS seleccionada y la disponibilidad de parches de seguridad:

### Certificación TCK y Recomendaciones

- **Certificación TCK**: Solo Oracle JDK y distribuciones verificadas como Eclipse Temurin (Adoptium) o Red Hat OpenJDK pasan el Technology Compatibility Kit, garantizando compatibilidad estándar. Las versiones no verificadas pueden no cumplir con la especificación Java SE.
- **Recomendación**: Para entornos de producción sin presupuesto de licencias Oracle, utilice Eclipse Temurin o Azul Zulu (versiones LTS).  Para empresas que ya tienen suscripciones Oracle o necesitan soporte comercial garantizado, Oracle JDK o Red Hat OpenJDK son las opciones más robustas. Evite versiones no LTS (como Java 24 o 26) para producción debido a su ciclo de vida de solo 6 meses.
