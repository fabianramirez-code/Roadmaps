# Ediciones: Java SE, Java EE renombrado a Jakarta EE, Java ME
## Que cubre cada una:
## 1. Java SE (Standard Edition)
- **Propósito:** Desarrollo de aplicaciones de escritorio, herramientas de línea de comandos, servicios backend generales y la base sobre la cual corren las demás ediciones.
- **Componentes clave:** La máquina virtual (JVM), el entorno de ejecución (JRE) y el kit de desarrollo (JDK), además de las APIs fundamentales (java.lang, java.util, colecciones, concurrencia, networking).
## 2. Jakarta EE (Antes Java EE) 
- ***Cambio de nombre:** Originalmente propiedad de Sun Microsystems y luego de Oracle como Java EE, en 2017 pasó a manos de la Eclipse Foundation y fue renombrado a Jakarta EE por restricciones de marca de Oracle.*
- **Propósito:** Desarrollo de aplicaciones corporativas robustas, servidores de aplicaciones (como WildFly, Payara, Open Liberty) y arquitecturas basadas en microservicios o monolitos empresariales.
- **Componentes clave:** APIs y especificaciones estándar como Jakarta Servlets, Jakarta Persistence (JPA), Jakarta RESTful Web Services (JAX-RS) y Jakarta CDI (Contexts and Dependency Injection).
## 3. Java ME (Micro Edition)
Diseñado para dispositivos con recursos altamente limitados de memoria, procesamiento y energía.
- **Propósito:** Históricamente utilizado para sistemas embebidos, tarjetas inteligentes (smart cards), decodificadores de TV y los antiguos teléfonos móviles (feature phones).
- **Estado actual:** Su uso comercial directo en móviles ha quedado prácticamente obsoleto frente a Android, pero sigue vigente en nichos especializados de IoT (Internet de las Cosas) y hardware industrial.
---
## Cuando elegir uno u otro: 
- Elige Java SE cuando: Desarrollas herramientas de línea de comandos (CLI), aplicaciones de escritorio, utilidades o servicios backend modernos utilizando frameworks ligeros (como Spring Boot, Quarkus o Micronaut) que corren directamente sobre Java SE.
- Elige Jakarta EE cuando: Construyes sistemas corporativos monolíticos masivos o estás obligado por normativas estrictas de la empresa a desplegar sobre un servidor de aplicaciones tradicional (WildFly, Payara).
> **Nota pragmática:** Hoy en día, elegir "Jakarta EE puro" en un servidor de aplicaciones tradicional es poco común para nuevos desarrollos. La norma actual es usar Java SE con runtimes o frameworks modernos que implementan las especificaciones por debajo de forma embebida.

> **Nota clave:** El punto de quiebre absoluto ocurre en Jakarta EE 9, donde todas las APIs migraron formalmente el prefijo de sus paquetes de `javax.*` a `jakarta.*`
