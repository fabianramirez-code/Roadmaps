# Herramientas retiradas

# `javah` (eliminado en 10), `jjs`/Nashorn (eliminado en 15, JEP 372), Pack200 (eliminado en 14, JEP 367)

Una JDK Enhancement Proposal (JEP) es una [propuesta numerada de mejora de OpenJDK](https://openjdk.org/jeps/0). Estas herramientas ya no forman parte del Java Development Kit (JDK, kit de desarrollo de Java):

| Herramienta | Qué hacía | Eliminada en | Alternativa |
|---|---|---|---|
| `javah` | Generaba cabeceras para Java Native Interface (JNI, interfaz para llamar código nativo desde Java). | Java 10 ([JEP 313](https://openjdk.org/jeps/313)) | [`javac -h`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html), que genera esas cabeceras; para nuevos enlaces con código nativo, valorar brevemente la [Foreign Function & Memory API (FFM, API de funciones externas y memoria)](https://openjdk.org/jeps/454), definitiva en Java 22. |
| `jjs` / Nashorn | Ejecutaba JavaScript desde el intérprete `jjs` o desde el motor Nashorn en la Java Virtual Machine (JVM, máquina virtual de Java). | Java 15 ([JEP 372](https://openjdk.org/jeps/372)) | Usar un motor externo como [GraalJS (GraalVM JavaScript)](https://www.graalvm.org/latest/reference-manual/js/) o ejecutar JavaScript fuera de la JVM. |
| `pack200` / `unpack200` (Pack200) | Comprimía y descomprimía archivos Java Archive (JAR, archivos de clases y recursos empaquetados) con un formato específico. | Java 14 ([JEP 367](https://openjdk.org/jeps/367)) | Compresión estándar con [`jar`/ZIP](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jar.html); para imágenes de ejecución, `jlink --compress` (nota 018). |

Para probar la alternativa de `javah`, crea `Prueba.java` con un método `native` (implementado en código nativo) en tu directorio de ejemplos; este ejemplo no requiere imports:

```java
public class Prueba {
    public native void saludar();
}
```

```bash
javac -h cabeceras -d clases Prueba.java # Genera cabeceras\Prueba.h y clases\Prueba.class
```

En el JDK 25 comprobado, `javah`, `jjs`, `pack200` y `unpack200` no aparecen ni en `PATH` ni en el directorio `bin` del JDK; la compilación anterior generó `Prueba.h` con la declaración `Java_Prueba_saludar`. No se necesita una sección de comandos para Linux/macOS: `javac -h` se usa igual.
