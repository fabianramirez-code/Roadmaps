# Classpath, Module path, Paquetes y estructura

# Classpath — resolución y orden, wildcard `lib/*`

El *classpath* indica dónde buscan clases las herramientas y el entorno de ejecución de Java: raíces de directorios con archivos `.class` o archivos Java Archive (JAR, paquetes de clases y recursos). Al buscar una clase, **se recorren las entradas de izquierda a derecha** y **gana la primera coincidencia**. Un directorio es una raíz de paquetes; un JAR contiene esas rutas dentro del archivo. Consulta los manuales oficiales de [`java`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html) y [`javac`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html).

| Opción | Uso |
|---|---|
| `-cp ruta` / `--class-path ruta` | Establece la búsqueda de clases para el comando; sustituye la variable de entorno `CLASSPATH` si se indica. |
| `CLASSPATH` | Búsqueda predeterminada si no se indica la opción; es preferible pasarla explícitamente para evitar sorpresas. |
| `"lib/*"` | Incluye los JAR directamente en `lib`, no subdirectorios ni archivos `.class` sueltos; **no se garantiza su orden**. Las comillas evitan que PowerShell interprete el comodín. |

En Windows, separa varias entradas con `;`. Para el ejemplo, crea los dos archivos siguientes (la clase principal importa expresamente la otra clase):

`src\com\ejemplo\util\Saludo.java`:

```java
package com.ejemplo.util;

public class Saludo {
    public static String texto() {
        return "Hola";
    }
}
```

`src\com\ejemplo\app\Main.java`:

```java
package com.ejemplo.app;

import com.ejemplo.util.Saludo;

public class Main {
    public static void main(String[] args) {
        System.out.println(Saludo.texto());
    }
}
```

Ninguna de las dos clases necesita importar `java.lang`, disponible automáticamente. Primero ejecuta desde el directorio de ejemplos con las dos clases compiladas en `out`; después empaqueta solo `Saludo` para mostrar la búsqueda en un JAR y vuelve a compilar `Main` en `app`:

```bash
javac -d out src\com\ejemplo\util\Saludo.java src\com\ejemplo\app\Main.java # Compila ambas clases
java -cp out com.ejemplo.app.Main # Hola
jar --create --file lib\saludo.jar -C out com/ejemplo/util/Saludo.class # lib debe existir
javac -cp lib\saludo.jar -d app src\com\ejemplo\app\Main.java # Compila solo Main
java -cp "app;lib/*" com.ejemplo.app.Main # Hola; PowerShell pasa el comodín a Java
```

También puedes compilar **desde la carpeta de esta nota**, no desde `Ejemplos_023`: coloca los dos archivos `src` del ejemplo anterior junto a la nota. El `Saludo.java` que ya está directamente en `Ejemplos_023` está vacío; no lo cambies ni lo uses como la clase `com.ejemplo.util.Saludo` (no genera ninguna clase). Las rutas entre comillas apuntan a `Ejemplos_023` aunque no sea el directorio actual:

```bash
# PowerShell: ejecuta desde la carpeta de esta nota
javac -d ".\Ejemplos_023\out" ".\src\com\ejemplo\util\Saludo.java" ".\src\com\ejemplo\app\Main.java" # Salida bajo Ejemplos_023\out
java -cp ".\Ejemplos_023\out;.\Ejemplos_023\lib/*" com.ejemplo.app.Main # Hola; lib puede estar vacía
```

No dependas del orden interno del comodín para resolver clases duplicadas.

# Module path — diferencia con classpath; ver [[Java 10 - Plataforma avanzada]]

El *module path* busca módulos con descriptor `module-info.class`. A diferencia del classpath, el [sistema de módulos de Java](https://openjdk.org/jeps/261) declara dependencias mediante `requires`, limita la visibilidad mediante `exports` (encapsulación fuerte) y detecta conflictos de paquetes divididos entre módulos resueltos. Un JAR sin descriptor colocado allí puede convertirse en **módulo automático**; las clases del classpath pertenecen al **módulo sin nombre**. Para profundizar: [[Java 10 - Plataforma avanzada]].

| Opción | Uso |
|---|---|
| `-p ruta` / `--module-path ruta` | Busca módulos en la ruta indicada. |
| `--add-modules com.ejemplo` | Agrega un módulo raíz para resolverlo; útil al combinar rutas de módulos y clases. |
| `-m com.ejemplo/com.ejemplo.app.Main` | Ejecuta la clase principal del módulo indicado. |

Crea `module-info.java` junto a `src` para convertir el mismo ejemplo en módulo; `java.base` es una dependencia implícita y no necesita `requires`:

```java
module com.ejemplo {
}
```

```bash
javac -d mods\com.ejemplo module-info.java src\com\ejemplo\util\Saludo.java src\com\ejemplo\app\Main.java # Compila el módulo
java --module-path mods --add-modules com.ejemplo -m com.ejemplo/com.ejemplo.app.Main # Hola
```

# Paquetes y estructura de directorios — convención dominio inverso

La declaración [`package`](https://docs.oracle.com/javase/specs/jls/se25/html/jls-7.html) da a la clase un nombre completo y organiza su espacio de nombres. Por convención, los paquetes empiezan por un dominio invertido (por ejemplo, `com.ejemplo`) y continúan con su función (`app`, `util`). La ruta bajo la raíz de fuentes refleja los componentes del paquete: `src\com\ejemplo\app\Main.java` declara `com.ejemplo.app`; `javac -d out` reproduce esa estructura bajo `out`. Para ejecutar una clase empaquetada se usa el **nombre completo**, no el nombre corto; `out` es la raíz del classpath, no `out\com\ejemplo\app`.

Si se busca `Main` sin su paquete, el JDK 25 en español muestra `Error: no se ha encontrado o cargado la clase principal Main` y `Causado por: java.lang.ClassNotFoundException: Main` (en inglés: `Could not find or load main class`). Si se ejecuta `Main` desde `app` sin el JAR de `Saludo`, aparece `java.lang.NoClassDefFoundError: com/ejemplo/util/Saludo`, causada por `ClassNotFoundException`: revisa la raíz, el nombre completo y las dependencias del classpath.

# Comandos para Linux/macOS

En rutas de archivos usa `/` y separa entradas del classpath con `:` en lugar de `;`; los demás argumentos no cambian. Para el ejemplo, sustituye las rutas de los comandos de Windows y ejecuta el caso con varias entradas así:

```bash
java -cp 'app:lib/*' com.ejemplo.app.Main # Hola
```
