# JAR, manifest, JAR ejecutable y fat JAR, Opciones -X, -XX y archivos

# JAR, manifest — `Main-Class`, `Class-Path`, `Multi-Release`

Un Java Archive (JAR) es un archivo ZIP con clases y recursos; la creación y el listado básicos ya están en la [nota 016](../01_4%20Herramientas%20de%20línea%20de%20comandos/016%20-%2001_4.2%20Lanzamiento%20de%20múltiples%20archivos,%20jshell,%20jar.md). En su raíz se ubican las rutas de las clases (`Principal.class`, o `com/ejemplo/Main.class`); `META-INF/MANIFEST.MF` es el **manifiesto** con metadatos, no una clase ([especificación oficial](https://docs.oracle.com/en/java/javase/25/docs/specs/jar/jar.html)).

| Atributo del manifiesto | Significado |
|---|---|
| `Main-Class: Principal` | Nombre completo de la clase con `main`; no lleva `.class`. |
| `Class-Path: lib/saludo.jar` | Dependencias externas: rutas relativas a la ubicación del JAR, separadas por espacios; no admite comodines como `lib/*`. |
| `Multi-Release: true` | Habilita clases alternativas en `META-INF/versions/N/` para Java N o posterior (N ≥ 9); prevalece la versión más alta compatible, si existe. |

El formato exige un salto de línea final y una línea vacía al terminar cada sección; cada línea física admite **como máximo 72 bytes** (no caracteres): las largas se continúan en la línea siguiente empezando con un espacio. No dupliques atributos. Los JAR de varias versiones se definieron en la [JDK Enhancement Proposal (JEP) 238](https://openjdk.org/jeps/238), disponible desde Java 9; la versión base debe poder ejecutarse en el Java anterior al de la variante.

Para practicar, reutiliza `Principal.java` y `Saludo.java` de la nota 016, desde tu directorio de ejemplos. Crea `lib` y un archivo `MANIFEST.MF` en ese directorio con estas líneas (incluida **una línea vacía al final**):

```text
Manifest-Version: 1.0
Main-Class: Principal
Class-Path: lib/saludo.jar
Multi-Release: true

```

Crea otra versión de `Saludo.java` bajo `v9` (misma firma que en la nota 016, pero distinto mensaje):

```java
public class Saludo {
    static String de(String nombre) { return "Hola Java 9+"; }
}
```

```bash
New-Item -ItemType Directory out, lib, v9 -Force | Out-Null # Prepara las rutas de salida
javac --release 8 -d out Principal.java Saludo.java # Versión base; JDK 25 puede avisar que 8 es antiguo
javac --release 9 -d v9 v9\Saludo.java # Variante para Java 9+
jar --create --file lib\saludo.jar -C out Saludo.class # Dependencia externa
jar --create --file app.jar --manifest MANIFEST.MF -C out Principal.class # Conserva el manifiesto propio
jar --create --file multi.jar --main-class Principal -C out Principal.class -C out Saludo.class --release 9 -C v9 Saludo.class # Añade la variante
```

Para leer **el manifiesto** sin extraer archivos, usa PowerShell: carga el JAR como ZIP, abre `META-INF/MANIFEST.MF` y cierra los lectores; también puedes extraerlo con el procedimiento de la nota 016. El [manual de `jar`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jar.html) describe `--manifest`, `--main-class` y `--release`.

```bash
Add-Type -AssemblyName System.IO.Compression.FileSystem # API de ZIP
$zip = [System.IO.Compression.ZipFile]::OpenRead((Resolve-Path .\multi.jar).Path)
try {
    $reader = [System.IO.StreamReader]::new($zip.GetEntry('META-INF/MANIFEST.MF').Open())
    try { $reader.ReadToEnd() } finally { $reader.Dispose() }
} finally { $zip.Dispose() } # Main-Class y Multi-Release
```

# JAR ejecutable y "fat JAR" — cuándo usarlos

`java -jar` inicia la clase declarada en `Main-Class`. La opción `-cp` se **ignora** al usar `-jar`: el classpath efectivo procede del JAR y de su manifiesto, no del valor indicado en la línea de comandos. Por eso `app.jar` necesita el archivo `lib/saludo.jar` junto a él (en su subdirectorio `lib`); sin esa dependencia, falla al cargar `Saludo`. `multi.jar`, en cambio, contiene ambas clases y en Java 9+ elige la variante ([manual oficial de `java`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html)). El orden de búsqueda y los comodines del classpath ordinario están en la [nota 023](023%20-%2001_5.1%20Classpath,%20Module%20path,%20Paquetes%20y%20estructura.md).

```bash
java -jar app.jar # Hola Java, usando lib/saludo.jar
java -cp "inexistente" -jar app.jar # Hola Java: -cp no sustituye Class-Path
java -jar multi.jar # Hola Java 9+ en JDK 25
```

Un **fat JAR** o *uber-jar* fusiona las clases y recursos de la aplicación y sus dependencias en un único archivo: útil para distribuir uno solo, pero puede haber conflictos de nombres de clases o recursos, firmas inválidas al modificar JAR firmados y un archivo más grande. Para dependencias separadas, prefiere `Class-Path` con `lib/`: permite reemplazarlas por separado, pero hay que distribuir el directorio completo. [Maven Shade](https://maven.apache.org/plugins/maven-shade-plugin/) y [Gradle Shadow](https://gradleup.com/shadow/) son herramientas para construir fat JAR; no basta con añadir JAR dentro de otro JAR. Los **JAR anidados** de [Spring Boot](https://docs.spring.io/spring-boot/specification/executable-jar/nested-jars.html) usan un cargador propio: no son el formato plano de un fat JAR ni los resuelve automáticamente el lanzador Java.

# Opciones -X, -XX y archivos @argfiles; variable JAVA_TOOL_OPTIONS

Las opciones `-X` son específicas de la implementación (no estándar): `-Xms` fija la memoria inicial del *heap*, `-Xmx` su máximo y `-Xss` el tamaño de pila por hilo. `-XX` agrupa opciones avanzadas de la máquina virtual: `-XX:+Flag` activa una opción booleana y `-XX:Flag=valor` asigna un valor; consulta disponibilidad y valores en **tu** JDK, pues pueden cambiar. `java -X` muestra las opciones `-X`; `-XX:+PrintFlagsFinal` lista los valores finales (se filtra para no imprimir miles de líneas). Véase el [manual de `java`](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#extra-options-for-java) y sus [opciones avanzadas](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#advanced-options-for-java).

```bash
java -X # Ayuda de opciones no estándar
java -Xmx64m -XX:+PrintFlagsFinal -version 2>&1 | Select-String 'MaxHeapSize' # Muestra el máximo aplicado
```

Un **archivo de argumentos** (`@argfile`) contiene opciones y argumentos del lanzador, separados por espacios o saltos de línea; `#` inicia un comentario y las comillas agrupan textos con espacios. Crea `args.txt` como texto simple en el directorio de ejemplos:

```text
# Opciones para ejecutar la aplicación
-Xmx64m
-jar "app.jar"
```

```bash
java @args.txt # Hola Java
```

El `@` lo expande el **lanzador** `java` antes de procesar argumentos: no es una lista de argumentos que interprete `main`, ni una opción de la máquina virtual; evita incluir secretos. Para impedir expansiones posteriores existe `--disable-@files`. La [documentación oficial de archivos de argumentos](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#java-command-line-argument-files) detalla el escape y las comillas.

`JAVA_TOOL_OPTIONS` inyecta opciones de la máquina virtual al crearla, incluso cuando no se invoca directamente `java`; no sirve para opciones exclusivas del lanzador como `-jar`. `JDK_JAVA_OPTIONS` antepone opciones a la línea del lanzador (rechaza, por ejemplo, `-jar` en la variable). En HotSpot también existe `_JAVA_OPTIONS`, propia de la implementación. **No dependas de una precedencia universal entre las tres**: el lanzador procesa `JDK_JAVA_OPTIONS` antes de sus argumentos, mientras que las otras se aplican al crear la máquina virtual; al repetir una opción comprueba el valor efectivo en tu JDK. Estas variables afectan a otros procesos Java de la sesión: retíralas al terminar ([entorno del lanzador](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html#using-the-jdk_java_options-launcher-environment-variable)).

```bash
$env:JAVA_TOOL_OPTIONS = '-Xmx64m'; java -jar app.jar; $env:JAVA_TOOL_OPTIONS = $null # stderr: Picked up JAVA_TOOL_OPTIONS: -Xmx64m
$env:JDK_JAVA_OPTIONS = '-Xmx128m'; java -version; $env:JDK_JAVA_OPTIONS = $null # stderr: NOTE: Picked up JDK_JAVA_OPTIONS: -Xmx128m
$env:_JAVA_OPTIONS = '-Xmx256m'; java -version; $env:_JAVA_OPTIONS = $null # stderr: Picked up _JAVA_OPTIONS: -Xmx256m (HotSpot)
```

# Comandos para Linux/macOS

Si no usas PowerShell, lee el manifiesto sin extraer el JAR con `unzip -p` (si `unzip` está instalado); para probar la variable de entorno solo durante ese proceso usa la asignación delante del comando. Las opciones de Java y las rutas internas del JAR no cambian.

```bash
unzip -p multi.jar META-INF/MANIFEST.MF # Muestra el manifiesto
JAVA_TOOL_OPTIONS='-Xmx64m' java -jar app.jar # Variable solo para este proceso
```
