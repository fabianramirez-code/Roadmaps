# Depurador, Depuración remota, Hot swap y limitaciones

# Depurador — breakpoints condicionales, watch, evaluate, step into/over/out

Un **punto de interrupción** (*breakpoint*) pausa un hilo en una línea para examinar la pila y las variables. Uno **condicional** solo pausa cuando su expresión es verdadera; por ejemplo, `i == 3` en un bucle. **Watch** muestra una expresión cada vez que se detiene la ejecución; **evaluate** la calcula en la pausa actual (evita llamar métodos que cambien el estado). [Guía oficial de depuración de IntelliJ IDEA](https://www.jetbrains.com/help/idea/debugging-code.html).

| Acción | Efecto al estar pausado |
|---|---|
| Step into | Entra en el método llamado en la línea. |
| Step over | Ejecuta la línea sin entrar en los métodos llamados. |
| Step out | Termina el método actual y vuelve al llamador. |
| Resume | Continúa hasta el siguiente breakpoint o el fin del programa. |

# Depuración remota —  `-agentlib:jdwp`

La [Java Platform Debugger Architecture (JPDA)](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/architecture.html) incluye el **Java Debug Wire Protocol (JDWP)**, protocolo entre el depurador y la máquina virtual Java (JVM). El agente `-agentlib:jdwp` habilita esa comunicación por red; [opciones oficiales](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/conninv.html#vm-invocation-options).

| Opción | Significado |
|---|---|
| `transport=dt_socket` | Usa un socket de red. |
| `server=y` / `server=n` | La JVM escucha al depurador / la JVM se conecta a un depurador que escucha. |
| `suspend=y` / `suspend=n` | Espera antes de ejecutar `main` hasta que se adjunte un depurador / comienza inmediatamente. |
| `address=127.0.0.1:5005` | Escucha solo en el equipo local, puerto 5005. |
| `address=*:5005` | Escucha en todas las interfaces: en JDK 9+ hace falta el `*` para permitir conexiones externas; sin él, `address=5005` escucha solo localmente ([opciones de conexión de JPDA](https://docs.oracle.com/en/java/javase/25/docs/specs/jpda/conninv.html)). |

**No expongas JDWP a redes no confiables ni lo habilites en producción**: quien se conecte puede controlar la ejecución y evaluar código. Para un equipo remoto, usa una red/túnel protegido y limita el acceso; en este ejercicio solo se escucha en localhost.

Ejemplo mínimo `Depura.java` (sin imports: `String`, `System` y `Thread` son de `java.lang`):

```java
public class Depura {
    public static void main(String[] args) throws InterruptedException {
        for (int i = 0; i < 15; i++) {
            Thread.sleep(500);
            System.out.println(saludar("Java"));
        }
    }

    static String saludar(String nombre) {
        return "Hola, " + nombre;
    }
}
```

En dos terminales PowerShell, desde el directorio donde guardaste el fuente, usa **el mismo kit de desarrollo de Java (JDK)** para los tres ejecutables (ajusta `$jdk` a tu instalación). El bucle da tiempo a adjuntar el depurador; `-g` conserva datos útiles para inspeccionar el código fuente.

```bash
$jdk = 'C:\Program Files\Eclipse Adoptium\jdk-25.0.5.10002-hotspot\bin' # Terminal 1
& "$jdk\javac.exe" -g Depura.java
& "$jdk\java.exe" -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=127.0.0.1:5005 Depura
```

```bash
$jdk = 'C:\Program Files\Eclipse Adoptium\jdk-25.0.5.10002-hotspot\bin' # Terminal 2; mientras sigue el bucle
& "$jdk\jdb.exe" -connect com.sun.jdi.SocketAttach:hostname=127.0.0.1,port=5005
# Dentro de jdb, antes de que termine el bucle:
stop in Depura.saludar
where
cont
exit
```

`where` funciona **después** de que el breakpoint detenga el hilo: muestra `Depura.saludar` y su llamador. En Windows, `jdb -attach 5005` puede seleccionar por defecto la conexión de memoria compartida y fallar con `shmemBase_attach failed`; `-connect com.sun.jdi.SocketAttach:...` elige explícitamente el socket. Para adjuntar desde un entorno cuyo conector predeterminado sea de socket, usa `jdb -attach 127.0.0.1:5005` ([manual de jdb](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jdb.html)). En un entorno de desarrollo integrado (IDE), crea una configuración **Remote JVM Debug** / **Remote Java Application** con host `localhost` y puerto `5005`, y pulsa **Debug**; no inicies el programa por segunda vez. Termina el proceso Java al acabar (o espera el fin del bucle).

# Hot swap y limitaciones — qué cambios admite la JVM sin reiniciar

**Hot swap** reemplaza una clase ya cargada durante una sesión de depuración. La redefinición estándar de clases admite cambios en **cuerpos de métodos** (por ejemplo, cambiar el texto devuelto por `saludar`) sin reiniciar; no permite añadir/quitar campos o métodos, cambiar firmas ni modificar la jerarquía de clases. Si editas `Depura.java`, recompila y pide al IDE que recargue las clases modificadas mientras la sesión siga conectada; si el cambio excede esos límites, reinicia el proceso. [Especificación oficial de redefinición de clases](https://docs.oracle.com/en/java/javase/25/docs/api/jdk.jdi/com/sun/jdi/VirtualMachine.html#redefineClasses(java.util.Map)).

# Comandos para Linux/macOS

En sistemas donde el conector predeterminado de `jdb` es socket, `-attach` evita la selección explícita del conector necesaria en Windows; mantén la dirección local del ejemplo.

```bash
jdb -attach 127.0.0.1:5005 # Adjunta al proceso Java iniciado con JDWP
```
